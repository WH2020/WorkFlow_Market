# A2 兼容适配与客户查询使用说明

- 状态：实现完成；正式数据迁移、存储切换和客户 360 页面仍未开放
- 适用范围：销售总监本地版，schema v1
- 关联设计：[SQLite 数据模型与迁移](ARCH-P0-SQLite数据模型与迁移.md)
- 前置能力：[A1 SQLite 存储与迁移](A1-SQLite存储与迁移使用说明.md)

## 1. A2 交付了什么

A2 把现有逻辑工具接到了统一业务存储接口，并保留迁移前的 CSV 兼容路径：

- `sales.read`：客户、互动、资源申请和销售资产查询；每张表有独立、不透明且绑定查询条件的游标。
- `sales.write`：兼容旧单表载荷；SQLite 模式支持一个 Approval 下的跨核心表短事务。
- `knowledge.search/write`：SQLite 模式查询 `sources`，并在同一事务中校验和写入 `evidence_refs`。
- `account.search`：按名称、负责人、地区、行业、阶段、健康度和项目筛选客户。
- `account.read_360`：按客户 ID 聚合关键人、机会、互动、承诺、风险、信号、行动、资源、资产、任务链接、产物和证据引用。
- `signals.read`：按客户、状态和严重程度读取确定性信号；CSV 兼容模式返回明确空集。
- 本机工作台只读接口：`GET /api/accounts`、`GET /api/accounts/{id}/360`、`GET /api/signals`。

A2 没有新增绕过任务系统的 HTTP 写接口。业务变更仍必须经过受管 DAG、精确载荷和人工 Approval。

## 2. 唯一存储选择规则

运行时只认项目内的 `data/storage-backend.json`：

| 状态 | 行为 |
|---|---|
| 指针不存在 | 使用现有 CSV，绑定值为 `csv:pointer-absent` |
| 指针是有效 schema v1 SQLite 配置 | 只使用指向的 SQLite 数据库 |
| 指针损坏、编码非法、是符号链接、路径越界、schema 不支持或数据库不可读 | 失败停止，不回退 CSV |
| 只有 `.db` 文件，没有指针 | 仍使用 CSV |

SQLite 启用后，周报快照、知识库页面、本地搜索和客户接口都读取同一后端。工作台的“打开知识库”不会再打开切换前的旧 CSV，也不会把 `.db` 交给任意外部软件编辑。

## 3. Approval 与存储绑定

每个 `sales.write` 和 `knowledge.write` 写入意图同时冻结：

1. 规范化业务载荷及 SHA-256。
2. 逻辑工具、任务和稳定会话身份。
3. 审批时的存储类型与 `binding_id`。

批准后出现以下任一变化都会阻止提交：载荷变化、记录版本变化、存储指针变化、旧任务缺少存储绑定，或同一 intent 已绑定另一内部事务信封。升级前已经批准但尚未提交的旧写入会被明确标记为不兼容，用户需要重新开始任务并基于当前数据生成内容；不会把旧 Approval 静默提交到新存储。

SQLite 提交把跨表 mutation、批准载荷哈希和回执写在一个短事务中。同一 intent 和相同内部信封重试返回原回执；同一 intent 的内容变化会被拒绝。CSV 模式继续使用原有文件锁、记录版本、提交日志和原子替换。

## 4. 查询约定

### 客户列表

```text
GET /api/accounts?query=脑机&owner=销售甲&region=江苏&limit=20
GET /api/accounts?query=脑机&limit=20&cursor=<上一页返回值>
```

`cursor` 绑定原查询和筛选条件。把某一查询的游标用于另一查询会返回 `INVALID_CURSOR`，不会从错误位置继续。

### 客户 360

```text
GET /api/accounts/account-001/360
GET /api/accounts/account-001/360?sections=contacts,activities,risks,signals,actions
GET /api/accounts/account-001/360?since=2026-08-01T00:00:00Z
```

每个分区最多返回 1,000 条；发生截断时通过 `truncated_sections` 明确报告。不存在的客户返回 404，未知分区和非法时间返回 400。

### 信号列表

```text
GET /api/signals?account_id=account-001&status=open&severity=high&limit=20
```

这些接口只监听本机工作台地址，并且只读。A3 才会把它们组合成面向销售总监的客户列表、上下文条、时间线和 360 页面。

## 5. 兼容与降级

- CSV 和 SQLite 都返回稳定客户字段、记录版本和受限结果；CSV 客户搜索也支持查询绑定游标。
- CSV 无法表达机会、信号、证据引用等关系时返回空分区，不把缺失数据编造成事实。
- SQLite 指针一旦生效，在线读取和周报快照不会因为查询失败而回到 CSV，也不会双写。
- `task_links` 和 `artifacts` 可作为批准的跨表 mutation 写入并由客户 360 聚合；A2 不自动回填历史任务或产物。
- 查询使用参数化 SQL、固定表/字段白名单、稳定排序、结果上限和只读连接；模型不能提交 SQL。

## 6. 当前仍不要做什么

- 不要在正式业务目录执行 A1 的 `activate-sales-store`。A5 的迁移向导、真实数据预检、观察期和恢复演练尚未完成。
- 不要手工创建或编辑 `data/storage-backend.json`；正式切换必须由迁移报告、数据库哈希和用户批准共同生成。
- 不要直接用数据库工具修改 `.db`。在线写入必须经过 Agent 的 Approval 与 Store 事务。
- 不要把 A2 查询 API 当作多人 CRM 服务；它只服务单用户、本机工作台。

## 7. 开发验收

正式运行时要求 Node.js 24.19.0 或更新的 Node 24 版本。A2 的主要回归命令为：

```text
python -m unittest discover -s tests -v
python -m unittest ui.test_server -v
pnpm check:types
pnpm test:runtime
pnpm test:sqlite-gate
python -m agent_platform validate
```

仓库测试只创建临时 fixture；不会扫描、迁移、激活或修改真实业务数据。
