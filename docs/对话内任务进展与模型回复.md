# 对话内任务进展与模型回复

2026-09-17：工作进展并入对话，不再要求在对话、任务页之间切换。任务请求下直接显示模型可见回复，随后是实际活动、执行步骤及审批 / 恢复操作。普通临时问答和任务对话仍有清晰标签：任务卡中的“排队补充 / 调整方向”发给该任务，底部普通消息框不会暗中变成任务指令。新普通对话不删除任务记录。

## 状态依据

- 核心在线：匹配任务、会话、角色且 15 秒内更新的租约心跳，仅说明进程在线。
- 模型 / 工具活动：Pi 的实际消息、工具生命周期事件；文字流活动只更新时间，不存储模型文本。
- 微信进度：原文批次或分层汇总的受控数字计数，不转发工具原文、聊天正文或任意工具详情。
- 单次模型 error / abort 先显示等待重试结果；只有 `agent_settled`（无自动重试或排队续接）才显示最终停止。无错误但 DAG 未结束时显示“本轮回复已结束，任务尚未完成”，可查看回复后继续。
- 2 分钟无执行反馈提示等待过久，10 分钟提示检查连接；不因为耗时长就擅自写为 failed。审批、取消及恢复仍由原有受控接口执行。
- 页面 3 秒轮询，状态请求有 10 秒超时；刷新失败会明确标记“状态未同步”，不将旧绿色状态继续解释为正在执行。恢复后自动显示新状态。

## 模型回复

仅读取该任务已绑定的原生 Pi JSONL 会话，不额外存储正文，也不搜索其他会话。API 接受任务编号和分页游标，不接受文件路径；校验当前用户、工作台令牌、Pi sessions 根目录、无链接 / 重解析跳转、header.cwd、结构化任务 state 的任务 / 角色 / workflow / session / 版本、当前分支。微信任务保留平台用户隔离门槛。

只显示 `assistant` 的 `text`，保持段落和全文，不执行 HTML、不加载模型给出的图片。隐藏推理、toolCall、toolResult、system / user 内部上下文、错误原始载荷与其他任务一律不返回。终态后的最终助手回复仍显示，但不拼接随后闲聊。

每页最多 12 条完整回复，页面内存去重并支持“加载后续回复”，刷新任务状态不重置正在阅读的位置。每页 / 单条 2 MiB、单行 8 MiB、会话 64 MiB 为读取安全上限；超限会明确提示，不把截断内容宣称为全文。读取中未写完的末行留待下次刷新。

限制：原生会话在 `message_end` 后落盘，因此任务回复按完整轮次展示，不是逐 token 流式；任务重启若改绑会话，只显示当前绑定会话，不自动拼接旧会话。若没有绑定租约提供当前分支，只允许读取无分叉会话；存在多个分支则提示无法确认，不按文件追加顺序猜测。尚无文件、不可用会话或超过读取上限均有明确提示。浏览器缓存不写 localStorage。现有运行中的核心需重启后才会发布新增活动字段；旧核心只能显示心跳和已有阶段记录。
