已证实优势

  • 持久 DAG、任务恢复、硬审批、冻结载荷和审计收据。
  • 公开检索、受控正文读取、PDF 页码证据、知识入库。
  • 可编辑 PPTX、逐页渲染与 QA、来源备注。
  • 项目空间、每日任务、自定义操作、模型与思考强度选择。
  • Windows/macOS 本地部署，不依赖 Codex Desktop。

已证实限制

  • 客户、活动、资源和销售资产仍分散在 CSV 与文件目录。
  • 没有正式的客户 360、关系图、承诺账本和信号收件箱。
  • 没有 CRM、销售邮箱、日历或通话记录的业务连接器。
  • 每日任务按时间触发，尚不能由商机变化或客户信号触发。
  • 不自动外发、改客户阶段或提交外部审批。

当前未知

  • 真实销售总监每周任务量、重复劳动时长和高频入口。
  • 客户数据目前主要来自何种 CRM、表格、邮件或人工记录。
  • 实际采用的销售方法论及阶段定义。
  • 任务建议被采纳后是否推动了客户阶段或缩短了跟进时间。
产品判断：下一阶段不应继续堆“服务按钮”。最有价值的改造，是让客户上下文、信号、下一步行动和复盘结果跨任务持续存在，使 Agent 从“接到任务后生成产物”升级为“持续帮助销售总监经营客户”。

自然语言总入口部分具备
首页快捷指令、服务卡与引导表单。		自然语言识别目标，再路由专业 Agent/Play。仍以“选择服务”为主要心智，跨服务目标需要用户自行拆分。P0目标识别器生成任务计划，只追问一个真正阻塞的问题。
销售 Play部分具备
固定 DAG、自定义操作、每日任务。		受众、信号、步骤、审批和产物组成可复用 Play。自定义操作尚不能保存为带版本的业务流程，也不能绑定信号。P0新增 Play Registry，支持从自然语言生成、预览、确认和复用。
客户 360缺失
客户、活动、资源和材料分别存储。		账户、关键人、互动、承诺、风险、材料和行动形成统一上下文。打开客户后不能一次看到“发生了什么、为什么、下一步是什么”。P0新增客户工作台与统一 Account Context API。
关系与承诺记忆部分具备
活动表含承诺与下一步字段。		关系角色、影响力、承诺、负责人、截止日期和兑现状态持续跟踪。承诺埋在活动记录中，缺少独立生命周期与到期提醒。P0拆出 stakeholder、commitment、open-loop 领域实体。
信号驱动缺失
只有人工和每日时间触发。		融资、招聘、互动、阶段变化、长期无活动等信号自动进入队列。Agent 不会因客户状态变化主动创建可解释的待办。P0Signal Store＋去重/过期规则＋Next Action Engine。
下一步行动队列部分具备
销售复盘可写 next_action。		按影响、紧迫度和证据排序，并说明推荐原因。没有跨客户排序、接受/忽略/稍后处理和结果反馈。P0首页改为可操作的“今日优先事项”，不是静态统计。
业务数据存储部分具备
CSV＋文件锁＋原子替换。		事务型关系存储承载账户、互动、任务、信号和审计。跨表一致性、关系查询、增量同步和并发扩展困难。P0SQLite 作为本地业务源；保留 CSV 导入/导出和原始文件。
销售方法论缺失
有阶段和风险，但无标准资格框架。		按 MEDDPICC、BANT、SPIN 等提取字段、证据和空缺。复盘难以跨客户比较，也无法判断缺失的是事实还是销售动作。P1方法论模板插件；字段必须附来源和确认状态。
CRM/邮箱/日历/会议接入缺失
报销邮箱只读且隔离于销售业务。		持续同步客户对象、邮件、会议和通话。销售总监仍需手工上传或录入关键上下文。P1Connector Gateway；先 CSV/Excel 导入，再接单一真实系统。
销售教练与趋势部分具备
支持单次销售复盘。		跨多次互动识别重复异议、承诺质量和行为变化。没有面向个人/团队的长期趋势与复盘闭环。P1先基于结构化记录做趋势，不做消息数量式人员评价。
质量评估与反馈部分具备
技术测试、验证器和审计较完整。		记录建议采纳率、资料准确率、行动完成率及业务结果。不能判断 Agent 是否真正减少工作或改善客户推进。P1Evaluation Store＋用户一键反馈＋任务结果回填。
文件与 PPT优势能力
资料、方案、PPT、逐页 QA、来源备注。		商业销售平台通常只生成草稿或简报。当前不是主要差距；继续扩充容易偏离客户经营主线。P2维持质量，优先让产物自动继承客户上下文与证据。
自动对外执行明确不做
不自动发送、改阶段或外部审批。		数字 SDR 自动发送、跟进和预约。自动化程度低，但当前安全边界合理。P2未来仅在连接器成熟后增加逐动作审批、限额和撤销。
多人协作/云端运营明确延期
本地单用户。		团队权限、共享账户、经理视图和集中审计。无法支撑多销售并行使用。P2当前第一用户仍是单个销售总监，不提前建设多租户。

SQLite 业务库（P0）

事务、关系查询、FTS、版本迁移、备份；CSV 继续作为导入导出格式。

证据与文件库（保留）

原始资料不动，记录来源、页码、哈希、状态和使用范围。

评估与运营层（P1）

采纳率、完成率、准确率、节省时间、失败类型和业务结果。

为什么推荐 SQLite，而不是继续扩展 CSV

  • 单用户桌面无需部署数据库服务，仍保持开箱即用。
  • 客户、关键人、承诺、信号和行动需要事务与关系查询。
  • 可以使用 WAL、完整备份、迁移版本和全文检索。
  • 保留 CSV 导入导出，避免锁死用户数据。

为什么不直接使用 Postgres 或向量数据库

  • Postgres 会增加安装、升级、端口和备份复杂度，不符合当前单用户范围。
  • 客户事实首先需要关系和状态一致性，不是相似度检索。
  • 向量索引可作为以后可替换的知识检索部件，不能充当业务源。
  • 原始文件继续保存在项目空间，数据库只存结构化记录和索引。

Guidance

分阶段改造顺序

不以日历工期承诺；每阶段以前一阶段数据契约稳定为入口条件。

阶段 A · P0

从任务助手变成客户经营助手

  1. 建立 SQLite 业务库和兼容导入/导出。
  2. 建立 Account 360、关键人、承诺、风险和证据模型。
  3. 建立 Signal Store 与下一步行动队列。
  4. 建立自然语言目标入口和可复用 Play。
  5. 首页改成“今日客户优先事项＋原因＋操作”。

阶段出口：不用先选择服务，输入一个客户目标即可得到可解释、可恢复、可执行的计划。

阶段 B · P1

减少人工搬运并形成复盘闭环

  1. 增加安全的 CSV/Excel 批量导入与字段映射。
  2. 选择一个真实 CRM 或销售邮箱做首个业务连接器。
  3. 增加销售方法论模板和缺口检测。
  4. 增加跨互动趋势、建议采纳和行动完成反馈。
  5. 将客户上下文自动传递给方案、PPT 与周报。

阶段出口：Agent 能持续更新客户事实、发现停滞并证明哪些建议有效。

阶段 C · P2

受控执行与团队化

  1. 增加邮件草稿、日程和 CRM 更新的逐动作审批。
  2. 增加限额、撤销、幂等与错误补偿。
  3. 评估多人协作、角色权限和团队共享。
  4. 评估 MCP/A2A 生态与第三方 Play 市场。
  5. 真实数据足够后再评估预测和自动优化。

阶段出口：安全边界可验证后，再把“建议”逐步扩展成“经批准执行”。

Acceptance

P0 可验证验收标准

每项都能转成自动测试与用户验收

客户 360 与数据迁移

  • 一个页面展示客户事实、阶段、关键人、承诺、风险、证据、行动、任务、资料和产物。
  • 每条事实含来源、状态、时间和适用范围；推断不能自动升级为事实。
  • 现有 CSV 可预览映射、校验、导入；失败不产生部分写入。
  • 数据库可备份、恢复并导出为不锁定用户的 CSV/JSON。

信号与下一步行动

  • 同一客户的重复信号可去重，过期信号不继续影响优先级。
  • 每条推荐显示触发信号、证据、推荐原因、截止日期和所需审批。
  • 用户可接受、编辑、忽略或稍后处理，并记录原因。
  • 推荐不会直接改变客户阶段、写入正式事实或对外发送。

目标入口与 Play

  • 用户可以直接输入“准备 A 客户拜访并找出推进障碍”，无需先理解服务分类。
  • 系统生成受众、资料、步骤、审批和产物预览；只追问一个阻塞性问题。
  • Play 有稳定 ID、版本、启停状态和变更记录，可被手动或定时触发。
  • Play 不能扩大 Profile 权限、绕过 DAG 或复用旧审批。

可靠性与回归

  • 应用崩溃后任务和信号租约可恢复，不重复写入或生成重复行动。
  • 迁移前后的客户、活动和资源记录数量、稳定 ID 与哈希可核对。
  • Windows/macOS 安装、升级、回滚和备份恢复均有自动化验证。
  • 现有研究、政府方案、PPT、周报、报销和文件回收功能全部回归通过。

Positioning

应保持的产品边界

继续强化

本地优先、证据可追溯、硬审批、政府合作、正式文件/PPT、可选模型、双平台桌面体验。

谨慎增加

CRM/邮箱/日历接入、销售方法论、跨客户分析；每项都要有来源身份、同步游标和撤销边界。

暂不承诺

无人值守外联、自动改变客户阶段、销售人员排名、成交预测、多租户云平台和个人微信读取。

推荐定位：“面向销售总监的本地客户经营与决策助手”，而不是“自动替代 SDR 的获客机器人”。差异化来自可信客户上下文、政府合作与正式材料能力，以及用户可控的本地数据和审批链。
