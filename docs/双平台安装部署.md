# Windows / macOS 安装部署

## 1. 支持范围

| 能力 | Windows 10/11 | macOS 13+ |
|---|---|---|
| Pi、Profile、DAG、Approval | 支持 | 支持 |
| 本地工作台 | 支持 | 支持 |
| 知识库与销售 CSV / SQLite schema v1 | 支持 | 支持 |
| 场景化公开搜索与受控网页读取 | 支持 | 支持 |
| 本地/在线 PDF 文本提取 | 支持 | 支持 |
| PPTX 生成和逐页 QA | 项目自带引擎 | 项目自带引擎 |
| 受控只读 Subagent | 前台独立子进程 | 前台独立子进程 |

这是单用户、本机部署。`.pi/`、真实 `data/`、`inputs/` 和 `outputs/` 只留在当前电脑，不自动同步、上传或外发。当前不提供云端多租户、局域网服务或无人值守服务器部署。

## 2. 前置条件

- Git。
- Python 3.11 或更高版本。
- Node.js 24.19.0 或更新的 Node 24 版本；Node 22、Node 25+ 和 Node 24.18 以前版本会被安装器拒绝。
- 能使用 npm；安装器在缺少 pnpm 时优先通过 Corepack 启用 pnpm 10。
- Pi 0.84.2 或更高版本；缺少时安装器会安装固定的 0.84.2，已有更高版本不会降级。项目依赖固定包含 `pi-subagents 0.51.0`，不需要用户另行安装。
- PPTX 生成依赖已经锁定在项目中的 PptxGenJS、PDF.js、JSZip 和本地 Canvas。真实逐页渲染使用开源 LibreOffice；安装器会检测并在缺失时安装。macOS 自动安装需要 Homebrew；没有 Homebrew 时可先从 LibreOffice 官网安装应用再运行 setup。

第三方 Pi Package 以当前用户权限运行。安装前应审阅仓库；执行安装器表示同意把当前 checkout 作为项目级 Pi Package 信任并安装（安装器会显式传递 `--approve`）。正式业务数据不要放入 Git。

## 3. Windows 安装

在 PowerShell 中执行：

```powershell
git clone https://github.com/WH2020/WorkFlow_Market.git
cd WorkFlow_Market
.\scripts\setup-windows.ps1
```

如果系统阻止当前终端执行本地脚本，可只为当前 PowerShell 进程允许已审阅脚本，再重新执行：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
.\scripts\setup-windows.ps1
```

常用可选参数：

- `-SkipDependencies`：已安装并锁定依赖时跳过 `pnpm install`。
- `-SkipPiInstall`：禁止安装器自动安装 Pi；Pi 缺失时停止。
- `-SkipLibreOfficeInstall`：禁止自动安装 LibreOffice；本机未安装时停止。

## 4. macOS 安装

推荐从 GitHub Actions 下载 `Agent4Market-macOS-universal-<commit>` 产物中的 `Agent4Market-universal-apple-darwin-runtime.zip`。它同时包含与应用匹配的代码和通用 `.app`：

```bash
ditto -x -k Agent4Market-universal-apple-darwin-runtime.zip .
cd Agent4Market
bash scripts/setup-macos.sh
```

安装器验证依赖后会把 `Agent4Market.app` 复制到 `~/Applications`，并在 `~/Library/Application Support/Agent4Market/install-root` 保存仅当前用户可读的运行目录关联。应用、真实业务数据和依赖仍然是一个本地安装整体；不要只移动 `.app` 后删除解压目录。

也可以从源码安装：

在 Terminal 中执行：

```bash
git clone https://github.com/WH2020/WorkFlow_Market.git
cd WorkFlow_Market
bash scripts/setup-macos.sh
```

源码安装没有同版本的预构建应用时，会自动安装 Rust 的 Apple Silicon/Intel 目标并构建通用 `Agent4Market.app` 与 DMG。单独重新构建可运行：

```bash
bash scripts/build-macos-desktop.sh
```

产物位于 `dist/macos/universal-apple-darwin/`，包括：

- `Agent4Market-universal-apple-darwin-runtime.zip`：推荐交付，包含应用和匹配代码。
- `Agent4Market-universal-apple-darwin-app.zip`：仅应用；使用前必须已有 setup 登记的完整运行目录。
- `Agent4Market-universal-apple-darwin.dmg`：常规拖拽安装镜像；同样依赖已登记的运行目录。
- `SHA256SUMS.txt`：三个产物的 SHA-256。

常用可选参数：

- `--skip-dependencies`
- `--skip-pi-install`
- `--skip-libreoffice-install`

如果全局 npm 目录没有当前用户写权限，不要直接使用 `sudo npm`。建议用 Homebrew、mise、nvm 等用户级 Node 管理方式安装 Node，再重试安装器。

## 5. 启动

Windows：

```powershell
.\Agent4Market.exe
```

setup 会使用 Rust/Tauri 2 在项目根目录生成 `Agent4Market.exe`，并自动执行 `--self-test`。双击 EXE 会同时启动销售总监桌面窗口、本地工作台和默认隐藏的嵌入式 AI 核心；工作台只访问 `127.0.0.1:8765`。在“设置 → AI 核心”可查看心跳与内嵌运行记录，也可选择下次启动时显示独立调试终端。启动器仅对它所在的已安装目录向 Pi 传递当次 `--approve`，不修改其他目录的信任状态。关闭桌面窗口时，程序会回收自己创建的工作台和 AI 核心进程树。

如果 8765 已被旧版本或其他程序占用，程序不会接管未知服务，而是显示中文启动错误。先关闭旧的 Agent4Market 窗口和手动启动的 `ui/server.py`，再双击重试。详细启动记录位于安装目录的 `.pi/director-runtime/desktop-launcher.log`。AI 核心终端是当前版本的受管执行界面，随桌面窗口打开属于正常现象；如果 Pi 提前退出，该终端会保留错误信息，不再一闪而过。

启动器只是当前安装目录的一键入口，不把 `data/`、模型密钥、Node、LibreOffice 或业务资料嵌入 EXE。因此不能单独把 EXE 复制到另一台空电脑；迁移时应复制整个安装目录并在目标电脑重新执行 setup。

macOS：

```bash
open "$HOME/Applications/Agent4Market.app"
```

双击或执行上述命令会同时启动桌面工作台和默认隐藏的销售总监智能核心。应用通过 setup 写入的本地标记找到完整运行目录；标记是普通绝对路径，不包含密钥。移动或删除运行目录后必须在新目录重新运行 setup。

当前 CI 产物使用 ad-hoc 签名，未使用 Apple Developer 证书和公证。首次打开时 macOS 仍可能拦截；请在 Finder 中按住 Control 点击应用并选择“打开”，或到“系统设置 → 隐私与安全性”确认。不要通过关闭 Gatekeeper 或执行来源不明的解除隔离命令来绕过检查。正式无警告分发仍需配置 Developer ID Application 证书和 Apple 公证。

底层脚本仍可用于开发诊断：

```text
Windows: python ui/server.py
macOS:   python3 ui/server.py
```

然后打开 `http://127.0.0.1:8765`。普通用户不需要这条路径。

## 6. 环境体检

```text
Windows: python -m agent_platform doctor
macOS:   python3 -m agent_platform doctor
```

报告区分：

- `core.ready`：操作系统、Python、Git、Node、pnpm、Pi 和插件契约均可用。
- `ppt.ready`：PptxGenJS、PDF.js、JSZip、本地 Canvas、构建/QA 脚本和 LibreOffice 均完整。
- `optional.public_search_ready`：报告公开检索是否可用；免密公共检索默认可用。
- `optional.brave_search_configured`：只报告是否配置专用 Brave 密钥，不显示密钥。
- `optional.local_data_initialized`：本地知识库和销售表是否初始化。

`core.ready` 还会核对两个发行版角色及其受控配置：公开研究员只能检索/读取公开来源，只读复核员没有工具；内置通用角色、后台任务、定时任务、Missions 和跨 Agent 通信必须保持关闭。安装器会合并这些固定设置，同时保留 Pi 配置文件中与本项目无关的字段。

将 PPT 作为强制条件：

```text
python -m agent_platform doctor --require-ppt
```

`agent_platform launch` 只在启动 Pi 子进程时临时注入已核验的 LibreOffice 路径、字体以及工作台安全存储中的模型/可选 Brave 专用密钥；免密公共检索不需要注入密钥。应用不会把明文密钥写入任务、日志、仓库或 Pi 模型目录。Windows 使用当前用户的 DPAPI，macOS 使用系统钥匙串。显式设置 `WORKFLOW_LIBREOFFICE_PATH` 但路径无效时不会静默改用另一个目录；`doctor` 会列出缺失项。

## 7. PPT 平台差异

- Windows 默认中文字体为 `Microsoft YaHei`。
- macOS 默认中文字体为 `PingFang SC`。
- 拉丁字体默认使用 `Arial`。
- 可以在启动前用 `WORKFLOW_CJK_FONT` 和 `WORKFLOW_LATIN_FONT` 明确覆盖。

不同平台的字体度量可能导致 PPTX 文件哈希不同，因此不承诺 Windows 和 macOS 生成字节完全一致；每台电脑都必须以本机逐页渲染和 QA 结果为准。正式载荷、来源、Profile、plan 和 Approval 的绑定规则不因平台变化。

## 8. 更新与回滚

更新前先确认没有运行中的任务：

```text
git pull --ff-only
```

然后重新运行对应平台的 setup 脚本。脚本不会覆盖已有知识库或销售数据；初始化器只创建缺失文件。代码回滚不应删除 `.pi/director-runtime/commits/`、任务状态、receipt 或业务 CSV。若任务处于 `committing`，先按使用说明完成恢复。

## 9. 验收

仓库的 CI 会在 `windows-latest` 和 Apple Silicon `macos-latest` 上实际运行对应安装器，安装或发现 LibreOffice，并执行相同的插件校验、TypeScript/Python/工作台测试以及真实 4 页 PPTX 生成、LibreOffice 转 PDF、PDF.js 逐页 PNG 和来源备注检查。macOS 作业同时交叉构建并按 macOS 的架构名称检查 `arm64` 与 `x86_64`、验证 ad-hoc 签名和桌面自检，再上传通用应用、DMG、完整运行包与校验和。Codex Desktop 不参与安装、运行或 CI。

建议每台新电脑完成三个验收任务：

1. 创建行业研究任务，验证网页读取和知识库检索。
2. 导入一份文本型 PDF，验证页码证据。
3. 生成一份 4 页测试 PPT，确认 PPTX、逐页 PNG、speaker notes 来源和溢出检查均通过。
