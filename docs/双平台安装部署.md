# Windows / macOS 安装部署

## 1. 支持范围

| 能力 | Windows 10/11 | macOS 13+ |
|---|---|---|
| Pi、Profile、DAG、Approval | 支持 | 支持 |
| 本地工作台 | 支持 | 支持 |
| 知识库与销售 CSV | 支持 | 支持 |
| Brave 搜索与受控网页读取 | 支持 | 支持 |
| 本地/在线 PDF 文本提取 | 支持 | 支持 |
| PPTX 生成和逐页 QA | 需要 Codex Desktop 演示运行时 | 需要 Codex Desktop 演示运行时 |

这是单用户、本机部署。`.pi/`、真实 `data/`、`inputs/` 和 `outputs/` 只留在当前电脑，不自动同步、上传或外发。当前不提供云端多租户、局域网服务或无人值守服务器部署。

## 2. 前置条件

- Git。
- Python 3.11 或更高版本。
- Node.js 22.19 或更高版本。
- 能使用 npm；安装器在缺少 pnpm 时优先通过 Corepack 启用 pnpm 10。
- Pi 0.84.2 或更高版本；缺少时安装器会安装固定的 0.84.2，已有更高版本不会降级。
- PPT 工作室需要当前用户目录下可用的 Codex Desktop 演示运行时；该依赖不随公开仓库重新分发。

第三方 Pi Package 以当前用户权限运行。安装前应审阅仓库；正式业务数据不要放入 Git。

## 3. Windows 安装

在 PowerShell 中执行：

```powershell
git clone https://github.com/WH2020/WorkFlow_Market.git
cd WorkFlow_Market
.\scripts\setup-windows.ps1
```

如果系统阻止当前终端执行本地脚本，可只为当前 PowerShell 进程允许已审阅脚本，再重新执行：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
.\scripts\setup-windows.ps1
```

要求安装过程在缺少 PPT 运行时时直接失败：

```powershell
.\scripts\setup-windows.ps1 -RequirePpt
```

常用可选参数：

- `-SkipDependencies`：已安装并锁定依赖时跳过 `pnpm install`。
- `-SkipPiInstall`：禁止安装器自动安装 Pi；Pi 缺失时停止。
- `-RequirePpt`：将 PPT 运行时作为安装成功的必要条件。

## 4. macOS 安装

在 Terminal 中执行：

```bash
git clone https://github.com/WH2020/WorkFlow_Market.git
cd WorkFlow_Market
bash scripts/setup-macos.sh
```

要求 PPT 同时可用：

```bash
bash scripts/setup-macos.sh --require-ppt
```

常用可选参数：

- `--skip-dependencies`
- `--skip-pi-install`
- `--require-ppt`

如果全局 npm 目录没有当前用户写权限，不要直接使用 `sudo npm`。建议用 Homebrew、mise、nvm 等用户级 Node 管理方式安装 Node，再重试安装器。

## 5. 启动

Windows：

```powershell
.\scripts\start-windows.ps1
```

macOS：

```bash
bash scripts/start-macos.sh
```

启动脚本会：

1. 切换到正确项目目录。
2. 自动发现并重新核验本机 PPT 运行时配置。
3. 运行核心环境体检。
4. 只向本次 Pi 子进程传递运行时路径和字体配置，不生成可被 source/dot-source 执行的环境脚本。

另开一个终端启动非技术工作台：

```text
Windows: python ui/server.py
macOS:   python3 ui/server.py
```

然后打开 `http://127.0.0.1:8765`。

## 6. 环境体检

```text
Windows: python -m agent_platform doctor
macOS:   python3 -m agent_platform doctor
```

报告区分：

- `core.ready`：操作系统、Python、Git、Node、pnpm、Pi 和插件契约均可用。
- `ppt.ready`：PPT 构建器、artifact-tool、marker、Python、渲染和 QA 路径均完整。
- `optional.brave_search_configured`：只报告是否配置，不显示密钥。
- `optional.local_data_initialized`：本地知识库和销售表是否初始化。

将 PPT 作为强制条件：

```text
python -m agent_platform doctor --require-ppt
```

`agent_platform launch` 只把发现结果放入 Pi 子进程环境，不持久化 Brave 密钥、模型密钥、登录态或本机路径。显式环境变量已设置但路径无效时不会静默改用另一个目录；`doctor` 会列出缺失项。

## 7. PPT 平台差异

- Windows 默认中文字体为 `Microsoft YaHei`。
- macOS 默认中文字体为 `PingFang SC`。
- 拉丁字体默认使用 `Arial`。
- 可以在启动前用 `WORKFLOW_CJK_FONT` 和 `WORKFLOW_LATIN_FONT` 明确覆盖。

不同平台的字体度量可能导致 PPTX 文件哈希不同，因此不承诺 Windows 和 macOS 生成字节完全一致；每台电脑都必须以本机逐页渲染和 QA 结果为准。正式载荷、来源、Profile、plan 和 Approval 的绑定规则不因平台变化。

## 8. 更新与回滚

更新前先确认没有运行中的任务：

```text
git pull --ff-only
```

然后重新运行对应平台的 setup 脚本。脚本不会覆盖已有知识库或销售数据；初始化器只创建缺失文件。代码回滚不应删除 `.pi/director-runtime/commits/`、任务状态、receipt 或业务 CSV。若任务处于 `committing`，先按使用说明完成恢复。

## 9. 验收

仓库的 CI 会在 `windows-latest` 和 `macos-latest` 上实际运行对应安装器，并执行相同的插件校验、TypeScript 测试、Python 测试和工作台测试。由于 Codex Desktop 演示运行时不能在公共 CI 中重新分发，CI 对 PPT 路径发现使用受控的 Windows/macOS 文件结构模拟；正式 PPTX 仍需在装有 Codex Desktop 的目标电脑上执行一次真实生成和逐页 QA。

建议每台新电脑完成三个验收任务：

1. 创建行业研究任务，验证网页读取和知识库检索。
2. 导入一份文本型 PDF，验证页码证据。
3. 生成一份 4 页测试 PPT，确认 PPTX、逐页 PNG、speaker notes 来源和溢出检查均通过。
