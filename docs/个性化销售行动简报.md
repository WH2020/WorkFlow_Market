# 个性化销售行动简报

## 目标

“销售行动简报”把同一份周报拆成两层：每位销售只看到与自己明确相关的客户进展、优先动作、资源需求和可用资料；销售总监看到团队汇总、待分配客户、资源阻塞和风险。用户只需按需填写一句“本周特别想强调什么”，不需要逐项制作周报。

## 使用流程

1. 在左侧打开“销售行动简报”。页面会自动读取本周本地销售资料并生成只读预览。
2. 先看“数据检查”。无法确认销售归属的客户会进入“待分配”，不会被模型猜给某人；未授权、状态无效、未核验或没有真实文件路径的资料不会进入推荐。
3. 展开每位销售的行动卡，查看最多 3 个优先动作、客户进展、资源申请和可用销售资料。每项会保留客户、跟进、行动、资源申请或资料编号。
4. 如有需要，在唯一的可选输入框补充本周重点，点击“生成个人简报＋总监汇报”。
5. Pi 会重新读取同一周期的权威数据，生成 SHA-256 校验并把完整快照保存到 `.pi/director-runtime/weekly-snapshots/`。同名快照不能覆盖。
6. 系统按“销售总监结论 → 各销售行动概览 → 重点客户进展 → 资源与资料 → 待分配/风险 → 下周行动”形成演示文稿内容。正式文件生成前仍须人工确认精确载荷。
7. 批准后才生成可编辑演示文稿并完成逐页检查。系统不会自动通过微信、邮箱、Slack 或其他渠道发送。

## 匹配规则

匹配按以下顺序执行，并且结果可解释：

1. 跟进记录或资源申请中的 `salesperson_id`。
2. 客户负责人字段与已启用销售人员的编号或姓名完全匹配。
3. 一条记录没有显式销售人员，但其客户只能确认归属给一位销售时，继承该唯一归属。
4. 仍无法确认时进入销售总监的“待分配”列表，不自动推断。

销售人员名单位于 `data/sales/salespeople.json`。只读取 `active=true` 的名单记录；如果本周期跟进或资源申请出现一个安全、明确的 `salesperson_id`，预览也会暂时为该编号生成行动卡，并提示后续完善姓名。

## 销售资料推荐门槛

一份销售资料必须同时满足以下条件才会进入个人行动卡：

- 有稳定资料编号和真实 `source_path`；
- 状态为有效、已发布、已核验、可用或同义受控状态；
- 授权状态为已授权、已批准或同义受控状态；
- SQLite 数据中的来源状态不是待核验、缺失或拒绝；
- 明确关联到该销售负责的客户，或资料负责人明确匹配该销售。

系统不会用标题拼凑不存在的下载地址，也不会把通用资料静默分发给所有人。

## 数据边界与当前限制

- 当前版本把本地 CSV 或已启用的 SQLite 作为事实来源，不自动连接 CRM、Slack 或企业数据仓库。
- 桌面页面是当前数据的只读预览；最终演示文稿只使用任务执行时重新冻结的快照。
- 快照包含业务原文，仅保存在本机且被 Git 忽略；不要提交业务数据或 `.pi/director-runtime/`。
- 当前只生成个人行动卡和销售总监演示文稿，不自动生成、发送每位销售的邮件或即时消息。
- 跨系统个性化分发可在后续接入企业身份、CRM 和消息渠道后单独设计权限与回执。

## 验收要点

- 销售总监 Profile 能完整执行周报快照、规划、校验、审批和演示文稿生成链路。
- 同一输入得到稳定的销售归属和行动排序；无法确认的客户不进入任何个人卡。
- 所有动作与资料都保留原始记录编号，资料路径来自真实数据。
- 新销售没有客户时显示补数提示，不显示空白卡片。
- 页面刷新不会改变用户滚动位置；只有用户进入页面或点击刷新时读取预览。
- 正式演示文稿仍需人工批准，且不会自动外发。
