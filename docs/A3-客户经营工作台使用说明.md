# A3 客户经营工作台使用说明

- 版本：0.14.0
- 适用范围：销售总监本地版
- 状态：工程实现与本地自动化验收完成；正式业务数据迁移和 A4 建议层未启用

## 已交付能力

工作台首页新增“今日关注”，只基于当前已登记的开放行动、承诺、资源申请、互动时间和信号生成查询时投影。每张卡片显示客户、关注原因、时间或截止日期以及首要操作，点击后进入对应客户分区。待批准写入仍在原“需要确认”区域处理，不与关注卡混为一类。

“客户经营”页面提供：

- 关键词、负责人、地区、行业、阶段、健康度和更新时间筛选，以及稳定游标分页。
- 最近互动、开放行动数、开放风险数和数据新鲜度。
- 明确可清空的当前客户上下文；顶部、客户页和快速输入框保持一致。
- 客户概览、证据化时间线、关键人、机会、行动与承诺、信号与风险、资源与资料、证据与任务八个分区。
- 客户复盘、政府合作、行业研究、资源协调/文件和演示文稿五类快捷入口。

快捷入口只预填客户名称、地区、阶段等已有上下文。它们创建新的受管任务，继续经过 DAG、来源核验、冻结载荷和 Approval；客户页没有新增直接业务写接口。

## 使用流程

```text
首页今日关注或客户经营
        ↓
筛选并选择客户
        ↓
查看全景、时间线与证据
        ↓
选择复盘 / 政府合作 / 研究 / 资源文件 / PPT
        ↓
核对已预填的任务说明
        ↓
受管任务执行 → 待批准内容 → 人工 Approval → 提交
```

要切换到无客户上下文的工作，点击顶部客户标签右侧“×”。应用不会在重启后静默恢复上次客户，也不会把前一个客户带入已打开的新任务。

## 数据后端差异

没有有效 `data/storage-backend.json` 时，页面读取现有 CSV：客户、互动、资源请求和销售资料继续可用；关键人关系、多机会、结构化承诺、证据关联、任务链接和写入回执会显示明确空状态。

只有通过迁移工具生成并显式激活的 schema v1 指针才会启用 SQLite。发现任意 `.db` 文件不会自动切换。A3 没有读取、迁移或激活正式业务数据。

## 交互与故障处理

- 切换客户时会取消旧请求，并用请求代次校验防止迟到响应串到新客户。
- 定时刷新使用渲染键，只在数据变化时更新客户区，不抢走输入焦点、不重置列表滚动或活动标签。
- 列表、全景、时间线和今日关注分别显示加载、空数据、部分失败和截断状态。
- 来源链接通过已有受控打开接口处理，不把任意本地路径或不受信 URL 交给页面直接打开。
- 扫描达到受控上限时返回明确错误，不把不完整结果伪装成完整数据。

## 自动化验收

- JavaScript 语法检查与工作台静态交互回归。
- CSV/SQLite 客户列表、客户全景、时间线、今日关注和 HTTP 契约测试。
- SQL 参数化、游标范围绑定、跨客户写入回执隔离、来源元数据和扫描截断测试。
- 临时生成 10,000 客户、100,000 条互动，每项运行 20 次：客户列表 P95 481.84 ms、客户全景 4.64 ms、时间线 3.68 ms、今日关注 63.61 ms，均低于 2,000 ms 目标。

性能数字来自当前 Windows 开发机的一次临时基准，只用于验证数量级，不代表所有设备的固定承诺。可运行：

```powershell
python scripts/benchmark_customer_operations.py
```
