# 智能招投标使用说明

## 适用范围

智能招投标是销售总监工作台中的本地项目空间，用于完成采购机会发现、招标文件解读、参投决策、应答策划、章节编制、合规复核、正式文件生成和结果复盘。它辅助用户组织证据与材料，不代替投标负责人、法务、财务或采购平台的最终判断。

当前版本不会自动登录采购平台、报名、报价、签章、加密、上传、发送或提交标书，也不处理验证码、电子签名和支付。

## 最短使用路径

1. 打开左侧“智能招投标”，点击“新建投标项目”。首次只需填写项目名称；采购人、编号、截止时间、关联客户和项目说明均可稍后补充。
2. 进入项目后，在页面底部选择“招标文件”并上传原件。文件只保存到当前投标项目目录，同名文件不会被覆盖。
3. 上传完成后选择“开始解读”。助手自动带入项目编号、当前阶段、客户、截止时间、已登记资料和当前缺口，不要求重复填写背景。
4. 每个阶段使用页面推荐的“下一步”，也可从右上角直接选择其他阶段。生成的业务更新先以中文卡片展示，可逐条编辑或删除，再由用户批准写入。
5. 在“合规复核”阶段先运行确定性检查，再让助手复核资格、强制条款、评分覆盖、材料、金额、日期、名称和递交风险。
6. 章节、事实和来源准备完成后，选择“生成正式标书”。批准后生成可编辑 DOCX，并在本机逐页渲染检查；成品可在“正式产物”中打开。
7. 投标完成后记录中标、未中标、废标、取消或待定结果，沉淀原因、复用资产和改进动作。

## 八个阶段

| 阶段 | 助手主要工作 | 用户确认点 |
|---|---|---|
| 机会发现 | 检索并打开公告正文，整理采购人、预算、期限、资格和原始链接 | 是否创建投标项目 |
| 文件解读 | 从已登记原件提取时间、资格、强制条款、评分点、格式和递交要求 | 待写入要求及其证据定位 |
| 参投决策 | 评估战略匹配、资格、交付、资源、商务、竞争和截止风险 | 参投、不参投或有条件参投 |
| 应答策划 | 建立逐条应答矩阵、材料清单、负责人、期限和事实基线 | 任务分工与缺口 |
| 章节编制 | 按已确认目录、事实和证据起草章节 | 正文、引用和未确认事实 |
| 合规复核 | 确定性规则检查加 AI 辅助复核 | 风险关闭、接受或退回修改 |
| 正式交付 | 生成 DOCX，渲染检查分页、乱码、空页和表格 | 冻结载荷与最终文件 |
| 结果复盘 | 记录结果、原因、复用资产和改进动作 | 结果事实与复盘结论 |

## 页面说明

- “项目总览”：项目状态、截止时间、参投结论和数量概览。
- “招标要求”：一条卡片对应一个可核验义务，保留文件及页码或段落定位。
- “应答矩阵”：要求、章节、策略、材料、负责人、截止时间、偏差和状态的对应关系。
- “标书章节”：已批准的目录、负责人、状态和引用证据。
- “合规检查”：规则编号、版本、严重程度、发现、建议和证据。
- “项目文件”：当前项目已登记原件，可校验哈希后快速打开。
- “正式产物”：经审批和渲染检查的 DOCX，可校验哈希后快速打开。
- “项目时间线”：建项、上传、检查、写入和生成等可追溯事件。

## 数据位置与安全边界

- 结构化投标数据：`data/bids/bidding.sqlite3`
- 原始资料：`inputs/bids/<bid_id>/`
- 正式产物：`outputs/bids/<bid_id>/`
- 文档生成回执与渲染证据：`.pi/director-runtime/document-commits/` 和 `.pi/director-runtime/document-jobs/`

这些目录均为本地业务数据，不应提交 Git。删除或移动原件会导致哈希校验失败；应先在工作台完成归档策略，再处理磁盘文件。当前首版不提供项目或证据的永久删除，以避免误删投标审计资料。

## 正式标书审批规则

- 正式文件只能引用当前项目已经登记且哈希一致的来源。
- 章节编号和标题必须与已批准目录一致。
- 使用专用的文档内容快照校验码；新增已生成产物不会使原任务重试失效，但项目、要求、事实、章节、检查或决策变化后必须重新确认。
- 输出文件名被占用时拒绝覆盖，请创建新版本名称。
- 关键问题未关闭时，助手不得宣称材料“可提交”或“零风险”。
