## 实现的功能

### 后端模块（已完成）

#### `agent_platform/model_provider.py`

1. **`detect_coding_assistants()`**
   - 检测本地 Claude Code 和 Codex CLI
   - 返回可执行文件路径和版本信息
   - 提供可用模型列表

2. **`configure_coding_assistant_provider()`**
   - 配置编码助手作为模型提供者
   - 保存版本 2 配置文件
   - 验证可执行文件存在性

3. **`load_model_settings()` - 增强**
   - 支持版本 1（NewAPI）和版本 2（编码助手）
   - 验证配置格式和字段
   - 返回结构化配置对象

4. **`model_settings_summary()` - 增强**
   - 根据版本返回不同的摘要信息
   - 版本 1：包含 base_url、models、has_api_key
   - 版本 2：包含 executable_path、provider_type

#### `ui/server.py`

1. **`GET /api/coding-assistants/detect`**
   - 调用 `detect_coding_assistants()`
   - 返回 JSON 格式的检测结果

2. **`POST /api/model-provider/configure`**
   - 接收提供者类型和配置参数
   - 支持三种类型：
     - `newapi` - 调用原有的 `configure_model_provider()`
     - `claude-code` - 调用 `configure_coding_assistant_provider()`
     - `codex-cli` - 调用 `configure_coding_assistant_provider()`
   - 返回配置结果和确认消息

3. **`configure_model_provider_choice()`**
   - 处理模型提供者配置请求
   - 路由到正确的配置函数
   - 统一的错误处理

## 使用场景

### 场景 1：使用 Claude Code

**适用于：**
- 个人开发者
- 需要直接使用 Claude 官方模型
- 已安装 Claude Code CLI

**配置步骤：**
1. 打开工作台设置页面
2. 选择"Claude Code"提供者
3. 确认检测到 Claude Code (显示绿色"已安装"状态)
4. 选择模型（推荐 Opus 5）
5. 保存并重启应用

**特点：**
- 使用本地 Anthropic API 密钥
- 支持 Claude 5 全系列模型
- 与 Claude Code 桌面应用共享配置

### 场景 2：使用 Codex CLI

**适用于：**
- 团队协作场景
- 统一使用 Codex 工具链
- 已部署 Codex CLI

**配置步骤：**
1. 选择"Codex CLI"提供者
2. 确认检测状态
3. 选择模型
4. 保存并重启

**特点：**
- 与 Codex 开发工具集成
- 支持团队级配置管理
- 模型选择相对保守（Opus/Sonnet）

### 场景 3：使用 NewAPI 网关

**适用于：**
- 需要多模型支持
- 使用第三方模型网关
- 需要自定义模型配置

**配置步骤：**
1. 选择"NewAPI 网关"提供者
2. 在 NewAPI 配置面板中填写网关地址和 API Key
3. 获取可用模型列表
4. 选择模型并保存

**特点：**
- 支持任意 OpenAI 兼容网关
- 可选择非 Claude 模型
- 网络化部署灵活

## 技术特点

### 1. 向后兼容

- 现有的版本 1 配置继续有效
- 升级后不影响已配置的 NewAPI 用户
- 配置迁移路径清晰

### 2. 自动检测

- 无需手动输入可执行文件路径
- 自动从 PATH 环境变量检测
- 显示版本信息供用户确认

### 3. 统一接口

- 所有提供者通过统一的配置 API
- 前端代码无需关心底层实现差异
- 便于后续扩展更多提供者类型

### 4. 审批一致性

- 无论使用哪种提供者，审批边界完全一致
- 编码助手不能绕过工作台的审批流程
- 数据安全和操作合规性得到保障
