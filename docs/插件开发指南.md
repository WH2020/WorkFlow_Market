# 插件开发指南

## 新增插件

在 `vertical_plugins/<category>/<name>/` 创建 `plugin.json` 和 `workflows/<workflow>.json`。Manifest 必须符合 `contracts/plugin.schema.json`。权限按最小集合声明；依赖必须给出插件 ID 和版本约束。不要把 Token、客户数据、公司模板或运行产物放入插件目录。

## 定义 Workflow

Workflow 必须符合 `contracts/workflow.schema.json`，并满足：

- `plugin` 与所属插件 ID 一致。
- `entry_nodes` 和 `output_nodes` 引用真实节点。
- `depends_on` 构成无环图。
- Tool 节点声明 `tool`，Approval 声明 `policy`，Validator 声明 `check`。
- Join 至少等待两个节点。
- Subagent 声明 `boundary.objective`、`allowed_tools`、`max_turns` 和 `write_scope`。
- 每个节点权限都在插件 `permissions` 内。

涉及知识库或销售台账写入时，把“准备变更”和“提交变更”拆成不同节点，并在写入 Tool 的祖先路径上设置 Approval。校验器会拒绝没有人工关口的 `knowledge.write` / `sales.write`。

## 接入逻辑工具

逻辑工具 ID 必须先加入 Python 契约校验器，再在 Pi 扩展中映射到具体的 `director_*` 适配器。适配器执行前和执行后都要向任务状态机核对当前节点；错误时不得推进状态。

结构化写入适配器至少满足：固定数据命名空间、稳定主键、字段白名单、读取版本校验、同表批处理、冻结载荷哈希、Approval 绑定、独占锁、提交前后文件哈希、同目录临时文件原子替换、不支持静默删除。每个结构化写 Tool 必须只有一个直接 Approval 前驱，一个 Approval 也只能直接保护一个结构化写节点。外部服务适配器必须显式配置密钥、固定可信端点、设置总超时、限制响应体和返回字段，并在不可用时停止当前节点。

正文与文件读取适配器还应限制协议、网络地址、重定向、Content-Type、响应大小、项目相对路径、普通文件类型和链接穿透。`web.open` 只能处理搜索返回或用户明确提供的公开 URL；`pdf.read` 只能读取 `inputs/` 或 `data/inbox/` 的明确 PDF。产物适配器必须限定输出目录和扩展名、拒绝覆盖，返回文件哈希与 QA 证据；演示文稿还必须经过 LibreOffice 真实逐页渲染，生成预览、来源备注，并检查 layout、画布边界、文本容量和重叠。

## 接入 Skill

Skill 放在 Pi Package 可访问的目录，并在 `pi/skill-catalog.json` 中登记“Skill 名 → 相对路径”。对应插件的 `skills` 字段决定哪些 Profile 会加载它；扩展通过 `resources_discover` 只加载当前 Profile 依赖闭包中的 Skills。不要把不属于任何新 Profile 的旧版邮箱或聊天 Skill 加入目录。

Skill 描述应明确“做什么”和“何时使用”，正文聚焦工作流、边界与质量门槛。新增或修改后运行 Codex `skill-creator` 的 `quick_validate.py`。

## 加入 Profile

编辑 `profiles/<profile-id>/profile.json`：

1. 把插件 ID 加入 `plugins`。
2. 在 `services` 中添加面向用户的服务。
3. 服务的 `workflow` 与 `skill` 必须由解析后的插件闭包提供。
4. 只有确实适合该岗位的服务才进入默认组合；可选实验能力以后放入高级管理界面。

新增岗位通常只需要新建 Profile 和领域插件，共享知识库、研究、文件、周报和 Pi 扩展无需复制。

## 本地验证

```powershell
python -m agent_platform validate
python -m unittest discover -s tests -p "test_agent_platform.py"
python -m agent_platform resolve-profile <profile-id>
python -m agent_platform list-services --profile <profile-id>
pnpm check:types
pnpm test:runtime
python -m unittest ui.test_server
```

合入前检查没有实际客户、员工、Token、私有模板或输出文件；依赖和 ID 无冲突；新权限有具体使用节点；高风险写入存在人工确认、恢复和审计；新 Agent 不引入微信、WeChat 或 WeFlow。

## 版本策略

- 兼容修改增加补丁版本。
- 新增兼容能力增加次版本。
- 破坏契约、权限或数据格式时增加主版本，并提供迁移和回退说明。
- Profile 应能固定插件版本组合；首版校验版本范围，但不自动迁移数据。
