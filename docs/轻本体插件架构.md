# 轻本体插件架构

## 1. 目标与范围

目标是让非技术用户打开后直接选择“市场总监”或“产品总监”的服务，同时让开发者可以单独增加、替换和升级领域能力。

当前基线实现：

- Pi 作为会话、模型与 Skill 运行时。
- 轻本体负责插件发现、依赖解析、权限校验、Profile 组合和 DAG 规划。
- 市场总监和产品总监两个开箱即用 Profile。
- Agent、Tool、Subagent、Approval、Parallel、Join、Validator 七类流程节点。
- 持久化任务状态、节点级工具门禁和不可由模型越过的 Approval。
- 知识库、销售台账、公开检索/正文/PDF 适配器、受控周报 PPT 及本地工作台。
- 现有知识库入口与事实分级规则。
- 新 Agent 不接入微信或 WeFlow。

当前不做云端多租户、自动对外发送、生产级分布式队列、跨表数据库事务和无人工确认的关键业务写入。界面采用仅本机访问的轻量 Web 工作台，不打包原生桌面壳。

本地文件锁记录进程 PID 和创建时间，但运行时不会自动删除疑似陈旧锁，避免并发回收竞态破坏独占性。崩溃恢复需要先停止相关进程并人工确认精确锁文件；结构化写入再由提交日志判断数据处于提交前、提交后或冲突状态。

## 2. 总体结构

```mermaid
flowchart TB
    UI[Pi TUI / 本地工作台] --> R[Profile Router]
    R --> MA[主 Agent]
    MA --> WP[DAG 状态机]
    WP --> EX[Node Gate / Adapter]
    EX --> AG[Agent Node]
    EX --> TL[Tool Node]
    EX --> SA[Bounded Subagent]
    EX --> AP[Hard Approval / Validator]
    AG --> PL[Vertical Plugins]
    TL --> PL
    SA --> PL
    PL --> KB[Knowledge Namespaces]
    PL --> DB[Business Ledgers]
    PL --> AR[Artifacts]
    AP --> DB
    AP --> AR
```

### Pi 层

Pi 提供模型调用、会话、命令、扩展和 Skills。`package.json` 是安装入口，`pi/extensions/vertical-workflow.ts` 提供岗位切换、按 Profile 动态加载 Skills、任务启动/恢复、工作台请求接管、审批命令和工具调用拦截。`task-runtime.ts` 维护版本化状态机，`data-adapters.ts` 提供受控 I/O。当前实现要求 Pi 0.84.2 或更高版本。

### 轻本体

轻本体不包含市场或产品规则，只提供：

- 插件 manifest 加载与版本依赖解析。
- Profile 组合及服务路由表。
- 节点权限与 Subagent 边界校验。
- DAG 无环校验和确定性执行计划。
- 任务状态、检查点、冻结写入、强制审批和工具适配的稳定接口；跨表迁移与回滚仍由后续版本补充。

### 插件与 Profile

插件拥有领域 Skill、DAG 工作流、权限声明和依赖。`shared` 插件可被多个岗位复用；`market` 和 `product` 插件承载领域规则。Profile 是面向用户的开箱组合，只暴露服务名称，不让真实用户逐个选择底层插件。

## 3. 主 Agent、DAG 与 Subagent

三者不是替代关系：

1. 主 Agent 识别意图、选择服务、补齐会改变方向的关键信息。
2. DAG 固定高价值流程的顺序、并行关系、审批点、写入点和输出门槛。
3. Subagent 只处理可以独立验收的研究分支、只读扫描或独立复核。

Subagent 节点必须声明目标、允许工具、最大轮次和写入范围。首版只允许只读 Subagent，非空写入范围会被校验器拒绝。数据库写入、正式文档生成、对外发送、客户阶段变更和发布决定不能交给无边界 Subagent 自由处理。

受管任务由状态机计算当前阶段。模型只能完成当前 `agent` / `validator` 节点；逻辑工具只有在与当前 Tool 节点唯一匹配时才可运行；Approval 只能由 `/director-approve`、`/director-reject` 或本地工作台请求推进。结构化写入的完整批次先规范化为 JSON 并计算 SHA-256，批准记录绑定写入意图和哈希，提交适配器只接受完全相同的载荷。Pi 的 `tool_call` 钩子会阻止跳步、等待审批期间的写入、受管任务中的通用 Bash，以及对 `data/` 的普通文件写入；`outputs/` 还会拒绝符号链接或目录联接穿透。该边界是应用级门禁，不等同于操作系统沙箱。

行业研究使用独立 Pi 子进程运行有边界的公开研究员，然后读取内部知识并由主 Agent 综合；政府合作草案使用一个无工具的只读复核员。每次调用都由主运行时生成绑定 task/profile/node/version 的短期合同，强制固定角色、前台执行、上下文模式、轮次、超时、工具白名单和 URL 范围，并记录来源及结果哈希回执。内置通用角色、后台运行、定时任务、Missions、跨 Agent 通信和子级再派生均关闭。Subagent 结果只能作为证据或复核意见，不能推进 Approval 或执行任何正式写入。

URL allow-set 和读取工具生成的精确入库 mutation 按任务持久化，重启后仍需匹配原证据。PDF 入库使用独立的 `pdf.read` → Agent 提取 → Validator → Approval → `knowledge.write` 工作流；周报使用 `weekly.snapshot` → Agent 编制精确载荷 → Validator 冻结 SHA-256 → Approval → `artifact.deck.write` 构建与 QA。载荷中的 Profile、周期、快照哈希、URL 和本地来源哈希必须与当前任务持久化快照一致，批准前不会生成 PPT。

## 4. 插件契约

| 字段 | 作用 |
|---|---|
| `api_version` | 轻本体接口版本 |
| `id` / `version` | 唯一身份与语义版本 |
| `category` | `shared`、`market` 或 `product` |
| `permissions` | 插件可申请的最小权限集合 |
| `dependencies` | 依赖插件及版本约束 |
| `skills` | 供 Pi 按需加载的能力 |
| `workflows` | 插件提供的 DAG 文件 |

Workflow 节点请求的权限必须是插件权限的子集。Profile 服务只能引用其最终依赖闭包中确实存在的 Workflow 与 Skill。

## 5. 知识库关联

`shared.knowledge` 是所有 Profile 的共同依赖，采用“原件不动、索引关联、证据可追溯”的方式接入当前知识库。

```mermaid
flowchart LR
    F[原始文件 / 来源登记 / 业务台账] --> I[知识索引]
    I --> S[任务知识快照]
    S --> W[DAG 节点分析]
    W --> C[冻结批次、记录版本与 SHA-256]
    C --> A[绑定载荷的 Approval]
    A --> M[提交日志与受控适配器合并]
    M --> I
```

知识记录至少保留稳定 ID、对象、陈述、状态、来源、证据位置、发生/发布日期、地域、有效期和访问范围。状态统一为“已证实事实、分析判断、待验证假设、未知信息”。冲突记录并列保存，以时间、地域、口径和来源解释差异。模型摘要不能自动升级为事实。当前所有知识库与销售台账写入都必须通过人工关口；涉及客户阶段、人员评价、正式产品决策或对外承诺时还应在拟更新清单中单独列出影响。

## 6. Profile 组合

市场总监复用研究、知识库、文件和周报，叠加政府合作与销售推进；输入来自用户上传、现有知识库和结构化销售台账，不包含聊天采集入口。

产品总监复用同一轻本体与共享插件，叠加产品发现、需求/PRD、指标与实验、路线图、发布评审。新增岗位不需要复制主 Agent、知识库或文档基础设施。

## 7. 升级与回滚原则

- 轻本体 API 与插件版本分别演进；插件通过语义版本声明兼容范围。
- 新插件先通过契约和 DAG 校验，再加入 Profile。
- 破坏性数据变更必须提供显式迁移、备份和回滚路径；首版不自动执行迁移。
- Profile 升级保留上一版本组合，失败时回退组合而不是删除用户数据。
- [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 的“Everything is a Plugin”用于设计借鉴，不作为首版强运行时依赖，避免受开发预览阶段兼容变更影响。

## 8. 验收标准

- 两个 Profile 均能解析出完整、无循环的插件依赖。
- 所有 Workflow 都是无环图，节点引用完整。
- 节点不能申请插件未声明的权限。
- Subagent 缺少边界时校验失败。
- 新 Profile 和解析后的插件内容不含微信、WeChat 或 WeFlow 引用。
- 产品总监具备发现、PRD、指标、路线图、发布和周报服务。
- Pi 能切换岗位、列出服务并用对应 Skill 启动任务。
- 受管任务重启后可恢复，模型不能完成 Approval 或跳过当前阶段。
- 本地工作台能提交任务、展示状态并只提交带版本的审批请求。
- 知识与销售更新拒绝未知字段、稳定 ID 覆盖和过期记录版本。
