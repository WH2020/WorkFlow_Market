# 应用内更新检测

> 本文保留 2026-09-10“仅检查和打开发布页”的实现与部署历史，不代表当前源码的一键更新能力。新的程序更新协议、签名门禁与验收状态见 [Windows 一键更新](Windows一键更新.md)和 [macOS 一键更新](macOS一键更新.md)。

## 使用范围

面向使用 Agent4Market 桌面版的用户，解决必须离开应用手动确认是否有新版的问题。入口为左侧“检查更新”和“设置 → 应用更新”。更新源按用户确认采用 GitHub Releases，固定仓库 `WH2020/WorkFlow_Market`，只检查正式发布频道。

首次启动页面时默认检查一次，应用打开期间约每 5 分钟检查，恢复可见或网络恢复时在冷却条件允许后检查。它是轮询，不是服务器推送；后台窗口节流、断网、GitHub 限流会延迟发现。关闭“自动检查更新”会保存当前浏览器/WebView 的偏好，不影响手动检查；关闭时已发出的只读检查可完成。独立浏览器配置之间不共享此偏好。

必须实现的状态包括：未检查、检查中、发现新版、已是公开最新版本、本机版本更高、更新源不可用、网络错误和限流。成功记录保留在进程内存，失败时可显示带时间戳的上次结果，但不得据此声称本次已成功检查。

“查看发布页”需要用户确认后才调用系统浏览器。发布者未必提供本机平台的安装包，因此按钮不承诺可以安装。自动下载、签名安装、就地覆盖、重启、数据迁移、私有仓库登录和自动对外发布均不在本版范围内。

## 实现与安全边界

- `agent_platform/app_updates.py`：从受限大小的 `package.json` 读取本机版本，按 SemVer 比较；单后台线程检查，内存状态、ETag、冷却和退避，不阻塞工作台请求。
- `ui/server.py`：`GET /api/app-updates` 只读快照；`POST /api/app-updates/check` 只接受 `manual` 布尔值；`POST /api/app-updates/open-release` 只接受已检测到的 `tag`。沿用本机/同用户校验，POST 需要应用请求令牌。
- `ui/app.js`：使用现有 3 秒 bootstrap 刷新取得检测结果，不把该刷新变成 GitHub 请求；使用服务实例 ID、递增修订号避免旧响应覆盖新结果。手动检查、后台检查和打开动作合并重复点击。
- 仅 GET 固定公共 GitHub API，不读取 GitHub Token、CLI 登录、模型配置或业务数据。网络传输可使用系统/环境代理，和模型网关分离。
- 请求拒绝重定向，响应上限 512 KiB；套接字超时 8 秒，分块读取检查 20 秒总时间预算，最后一次阻塞读取可能额外占用套接字超时。失败输出固定安全提示，不回显原始响应。
- 只接受带明确发布时间的正式版本，忽略上游提供的网页或资产 URL；发布页地址根据固定仓库和校验后的标签构造。更新说明是限长纯文本，不执行 HTML 或脚本。
- 手动最短间隔 60 秒，自动正常间隔 300 秒。连续失败自动指数退避并增加抖动，最高约 6 小时；GitHub 指定的限流等待最长按 24 小时处理。手动操作也不能绕过服务端限流。

未认证 GitHub REST API 按来源公网 IP 共享每小时 60 次主配额。单实例正常自动检查约 12 次/小时；多人共享出口时可能争用。ETag 可减少响应传输，但本功能不依赖它豁免未认证配额。限流时会延后，不承诺严格的 5 分钟可用性。[GitHub REST API 配额](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)

## 发布前提

2026-09-10 只读检查时，`https://api.github.com/repos/WH2020/WorkFlow_Market/releases/latest` 返回 HTTP 404。该结果不能区分私有仓库、没有正式 Release 或仓库地址变化，不能据此宣称没有新版本。

维护者发布时需要：

1. 确认分发用仓库及正式 Release 可被未登录用户访问；如果源码需要保持私有，可另行决定使用只放发行产物的公开仓库，并显式修改固定源。
2. 使用严格 SemVer 标签，例如 `v0.20.3`；与 `package.json`、Tauri/Cargo 版本一致。不勾选 Draft 或 Pre-release，并正确指定 GitHub 的最新正式发布。
3. 提供适用平台的安装包/便携包、完整更新说明、校验摘要和升级/回退步骤。当前客户端不下载、校验或执行资产。
4. 用实际发布包验证“检测到新版 → 查看发布页 → 用户确认”，不能拿本地合成测试版本当作已发布版本。

Windows 私有打包从 tracked 文件和显式 reviewed-untracked 白名单取源码；白名单已补入 `app_updates.py` 和 `cli_model_catalog.py`。macOS 的现有 `build-macos-desktop.sh` 使用 `git archive HEAD` 生成 Python runtime 包，只含已提交源码；不能从脏工作树直接声称构建包含本功能的 macOS runtime。本轮未构建 macOS 包，也未提交或发布任何 GitHub Release。

未来如需真正的一键安装，应另行设计签名校验、关停、备份、事务式替换和回滚，并适配安装器。Tauri 官方 updater 要求更新签名；现有按新目录安装的 Windows 安装器不是已验证的就地更新器。[Tauri Updater](https://v2.tauri.app/plugin/updater/)


可选浏览器验收使用已安装的 Edge 和 Playwright，无需新下载浏览器。运行 `tests/ui-app-updates-browser.mjs`，可通过 `A4M_BROWSER_PLAYWRIGHT` 指定 Playwright 模块路径、`A4M_BROWSER_PYTHON` 指定 Python。该脚本启动受控测试服务，覆盖新版徽标、版本/说明、确认/取消、关闭自动检测并重载、手动检测、当前更高版本、404/断网/限流和窄窗口；打开发布页被替换为只记录 URL 的适配器，不访问真实发布页。
