# 业务资料库与对话工作台

本次将已确认的交互原型落入正式工作台，不迁移真实台账，不自动调用模型，不改动微信原库。

## 使用路径

- 对话：普通问答沿用临时、无工具聊天。输入“复盘客户进展”“制作 8 页 PPT”“解读文件”等明确任务，转为对应工作流表单；用户确认开始后才创建任务。识别错误可手动切换工作流。
- 资料库：销售、客户、项目、文件、微信会话。可搜索、按负责人和归档状态筛选，维护联系人、跟进、行动与里程碑，并关联原始资料。
- 任务进展已并入「对话 → 任务对话」：模型可见回复、实际运行状态、任务步骤、审批与成果在同处显示，原工作进展链接自动转到对话。尚未接手的请求刷新后仍显示；历史任务与回复折叠保留。完成任务可从档案的“工作与成果”核对后保存一条本地行动，不自动提取建议为业务事实。
- 旧客户经营、投标、项目空间、定时任务等入口保留在“设置 → 其他工具与历史入口”。

2026-10-23 用户体验调整：客户档案的「围绕此对象发起对话」现在会将所选客户的有限背景用于普通问答，回复显示同源客户资料卡，确认后可将本轮记录保存回客户档案。只选择该客户，不读取其关联项目、联系人详情、文件正文或微信原文。客户背景由显式选择固定；要改为其他客户或项目，需要更换资料范围，已有对话仍需确认重新开始。输入区的「对话使用档案背景」可关闭本轮档案读取。

档案记录与正式经营数据仍保持现有边界。保存行动后会明确提示尚未纳入正式销售台账或销售行动简报；资料库列表和销售简报生成页也显示相同口径。简报页提供「核对经营台账」入口。本次没有迁移或回写正式业务数据，不能据此认为档案新增客户已自动进入销售统计。

## 对话中的项目索引

项目索引是现有档案和关联关系的只读派生视图，不新建一份项目数据库，不部署向量库或知识图谱服务。名称、用户填写的简称 / 别名用于明确匹配；去掉“项目”后的名称、关联客户或负责人用于候选提示。简称在“资料库 → 项目 → 编辑档案”维护，多个简称用逗号分隔。所有候选仍使用稳定项目编号，不按同名合并。

对话默认开启“对话使用档案背景”，可在输入框上方关闭。问题提交后先在本机匹配：唯一明确匹配自动带入，多项目或弱匹配先显示候选，选择之前不发送本轮问题给模型；未找到时不套用其他项目，提及“项目”时提供前往项目资料库的入口。明确使用“它 / 这个项目”等指代的追问沿用当前项目，不将任意陌生名称当成追问。有已完成的对话后，首次进入项目、切换或解除项目背景都需确认开始新对话，隔离不同范围的历史；取消或关闭失败不会改动原资料选择与工作空间。

触发工作流时，仍保留用户已选的工作流背景和资料供表单核对；没有明确识别出新项目时不会自动把工作流切到另一项目。普通对话的自动检索与工作流的手动资料选择是不同范围，工作流执行前仍需核对项目与资料。

实际发送的背景由服务器重读、校验版本并构造，只含项目名称、简称、客户与负责人姓名、阶段、说明、最近 8 条已保存的跟进 / 行动 / 里程碑、缺项、来源变化警示及来源 / 检索时间。背景总量不超过 24 KiB 并计入模型上下文预算；长记录截断且明确标示，不代表全部项目历史。工作进展中尚未核对保存到档案的结果不会自动变成项目事实。关联文件仅统计引用数量，不读取正文；不会沿关联关系读取微信群、联系人详情或其他客户档案。

模型仍无工具，不能自行扫描文件、查微信、写档案或批准任务。普通对话只把本轮服务器背景作为参考数据，不作为系统指令；来源不全、过期或冲突时须明确说明。档案在检索与发送间发生变化会拒绝旧版本，重新发送即可检索最新资料。完整对话和背景只在内存中使用，未增加后台扫描、自动保存对话事实或自动建档。

对话现在同时显示项目资料卡、最近记录及缺项。成功的项目轮次可通过内嵌表单补充信息：“仅用于追问”不保存，“确认保存到项目”才追加带来源的跟进/行动/里程碑。草稿来自用户原话，明确标为待确认，不自动提取模型建议为事实。服务端绑定已完成轮次和项目，不允许客户端换写入对象；同一轮重复提交去重，不自动修改客户阶段。新记录参与下一轮项目索引的最近 8 条范围。

回答偏好与业务档案分开：仅允许用户确认的详略、结构、格式、语言四类设置，存储于同一 SQLite 的独立表中，不参与项目档案版本计算。可在对话中查看、修改、忘记和关闭应用。当前没有隐式行为画像或图数据库，详见《自由聊天》的“对话内卡片与明确记忆”。

## 数据与权限边界

2026-10-24：对话可整理为可编辑的任务需求与最多 3 步的连续计划；短追问保留当前已匹配项目。已登记的计划与需求保存在原有任务/请求记录的 `handoff` 字段中，不建立另一份聊天库。后续步骤需上一项完成、用户核对可见结果后单独启动；服务端校验来源、版本、顺序及项目/档案范围，原有资料权限和审批条件继续生效。范围、限制与操作步骤见《自由聊天》的“从讨论继续工作”。

任务回复与状态的详细边界、测试和限制见《对话内任务进展与模型回复》。主导航现在保留「对话、资料库」，不再单设工作进展页面。

本地扩展档案位于 `data/library/dossiers.sqlite3`。销售名册、客户台账与原生项目空间为只读投影，使用稳定来源编号关联，绝不按同名自动合并。负责人文字没有可靠编号时保留历史名称，用户自行关联人员。

扩展档案保存显式覆盖字段、联系人和记录；未改写的字段跟随来源更新。来源变化会提示核对，编辑其他字段不会清除来源警示。归档保留资料与记录，不删除原件。原生项目归档沿用现有逻辑，停用其定时任务；恢复不会擅自重新启用。

任务开始时由服务端冻结所选档案与最多 20 个文件引用。项目档案必须匹配实际任务空间，项目文件不能跨空间混用；文件单份上限为 32 MiB。本地文件保存内容 SHA-256，PDF 读取器对实际解析字节复核，变更后须新建任务；重启不会自动接受变更内容。带此背景的任务禁止通用文件读取/目录扫描，防止扩大选中范围。所选公开网页仍经过现有网络安全检查；普通公开研究检索保持原服务权限。

当前本地正文读取只支持受控 PDF；其他格式在本次背景中仅提供文件引用，不宣称已经解析。需要分析非 PDF 文件时先转换为 PDF。任务背景不是写入审批，正式台账、PPT 和其他正式产物沿用原来的 DAG 与人工确认。

微信入口提供“准备聊天记录（复制 → 解析副本）”，串联原有复制与解析；仍可分步操作、重试解析而不重新复制。现有静态副本、WAL、账号、密钥或进程取钥授权条件不变。

客户群、销售群分类由用户设置，不按群名推断；可关联销售、客户、项目，仅改变引用。筛选只作用于当前已加载会话；最终确认列出所选会话，并标明筛选外仍勾选的数量。微信任务仅附带单独确认的会话范围，不携带对话中选中的其他档案或文件。平台入口限制与私有数据目录校验保持不变。
