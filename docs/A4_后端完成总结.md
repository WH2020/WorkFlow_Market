## 一、已交付内容

### 1. 核心业务层（4个模块）

#### a. 信号引擎 ([signal_engine.py](../agent_platform/signal_engine.py))
- 3 条规则：`OverdueActionRule`、`LongInactiveRule`、`CommitmentDueRule`
- 可扩展架构：`SignalRule` 基类 + `SignalEngine.add_rule()`
- 配置驱动：`signals_config.json` 外部化阈值（30天无互动、7天承诺预警）
- 按严重程度排序（high > medium > low）
- 单客户评估 < 10ms

#### b. 行动建议生成器 ([action_recommender.py](../agent_platform/action_recommender.py))
- 信号 → 建议转换：`generate_from_signal(signal, account_context)`
- 三种用户响应：接受（`accept_recommendation`）、编辑后接受、忽略（`ignore_recommendation`）
- 采纳率统计：`get_adoption_rate()` 返回 total/accepted/edited/ignored/pending/adoption_rate
- **写穿模式**：配置 store 后，生成/接受/编辑/忽略四个写入点同步落盘

#### c. Play 匹配器 ([play_matcher.py](../agent_platform/play_matcher.py))
- 5 个预定义 Play：sales_review、government_proposal、industry_research、presentation、resource_coordination
- 自然语言意图识别：关键词评分 + 上下文完整性检查
- 三种返回状态：`no_match`（无匹配+建议）、`need_more_info`（补问缺失字段）、`ready`（完整上下文+执行计划）

#### d. 工作流集成器 ([workflow_integration.py](../agent_platform/workflow_integration.py))
- 连接 Play 匹配器 → 信号引擎 → 建议生成器 → DAG 工作流系统
- `prepare_workflow_context(user_input, account_data)` 一站式准备执行上下文
- `enrich_workflow_input(workflow_id, base_input)` 自动附加待处理建议（最多5个）
- `validate_workflow_input(workflow_id, provided_input)` 验证必填字段
- Workflow↔Play 映射：4 个主工作流已覆盖

### 2. 持久化层 ([a4_store.py](../agent_platform/a4_store.py))

**设计决策**：独立 SQLite 数据库，不复用 `001_sales_core.sql` 的表

**原因**：
- `action_suggestions.account_id` 强制外键到 `accounts`，写建议需先伪造 `accounts` 行——违反「不代替用户写业务库」约束
- `signals.signal_type` CHECK 允许 `stale_account/missing_critical_field/resource_deadline`，与 A4 的 `long_inactive/missing_fields/resource_due` 不匹配
- `signals` 强制要求 `rule_version`、`evidence_version_hash`、`fingerprint` 等业务字段，A4 的 `Signal` 不具备
- 主库表保存已批准的业务记录，A4 保存待审批的工作状态，两者职责分离

**实现细节**：
- 3 张表：`a4_recommendations`（建议）、`a4_accepted_actions`（已接受行动，外键到建议表）、`a4_metadata`（版本和时间戳）
- 路径：`.pi/director-runtime/a4-recommendations.db`（`.gitignore` 已覆盖）
- 沿用 `sales_store.py` 约定：
  - `_configure()` 的 PRAGMA（`foreign_keys=ON`、WAL、`synchronous=FULL`）
  - 带 `.code` 的 `A4StoreError` 类
  - Z 后缀 UTC 时间戳（`datetime.now(timezone.utc).isoformat(...).replace("+00:00","Z")`）
- **向后兼容**：不传 `store` 参数则纯内存模式，既有 209 个测试一行未改

**已修复 bug**：空表上 `SUM()` 返回 NULL 而非 0，用 `COALESCE(SUM(...), 0)` 修正

### 3. API 层 ([a4_api.py](../agent_platform/a4_api.py))

**框架无关设计**：dict-in/dict-out，不耦合 `ThreadingHTTPServer`

**8 个处理器**：
1. `handle_match_play` - Play 匹配
2. `handle_evaluate_signals` - 评估客户信号
3. `handle_get_recommendations` - 获取待处理建议（可选按 account_id 过滤）
4. `handle_accept_recommendation` - 接受建议（支持 user_edits/assignee/due_at）
5. `handle_ignore_recommendation` - 忽略建议
6. `handle_validate_workflow_input` - 验证工作流输入
7. `handle_get_workflow_summary` - 获取工作流摘要
8. `handle_get_adoption_rate` - 获取采纳率统计

**响应格式**：
- 成功：`{"success": True, "data": {...}}`
- 失败：`{"error": str, "status": 400|404|500}`

**错误映射**：ValueError → 404，Exception → 500，缺失必填字段 → 400

## 四、安全边界遵守情况

✅ **硬审批机制**：建议生成后必须由用户明确接受/忽略，模型不能越过  
✅ **本地运行**：所有数据落在 `.pi/director-runtime/`，不离开本机  
✅ **不代替用户写业务库**：A4 存储独立于 `sales_store`，正式落库仍需工作台确认  
✅ **可追溯性**：所有接受/编辑/忽略操作记录到 SQLite，采纳率可统计  
✅ **幂等性**：相同客户数据多次评估返回相同信号列表  
✅ **路径限制**：数据库文件路径已被 `.gitignore` 覆盖，不会意外提交

## 八、技术亮点

1. **写穿 + 读缓存架构**：内存作读缓存，写操作同步落盘，兼顾性能和数据安全
2. **职责分离**：A4 存储只管工作状态，业务记录交给 `sales_store`，清晰的边界
3. **向后兼容**：不传 `store` 参数则纯内存，既有代码和测试零影响
4. **框架无关 API**：dict-in/dict-out 设计，未来可切换到 FastAPI/Flask 而不重写业务逻辑
5. **可扩展规则引擎**：`SignalRule` 基类 + 注册机制，新增规则无需修改引擎核心
6. **端到端类型安全**：`from __future__ import annotations` + `Literal` 枚举，消灭魔法字符串
