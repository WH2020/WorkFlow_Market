# 自由聊天

入口在左侧导航「对话」。它用于问答、讨论想法和润色主动输入的文字；明确的工作指令会打开相应工作流，核对并确认后才创建任务。旧「任务助手」仍保留在其他工具中。

## 使用

1. 先在设置中配置模型，再进入自由聊天选择「对话模型」和思考强度。
2. Enter 发送，Shift + Enter 换行；生成期间可点击「停止生成」。
3. 可继续追问；切换工作台页面不清空对话。「新对话」会结束当前会话，并允许重新选择模型。
4. 输入框上方可开关「对话使用档案背景」。未显式选定客户时，按项目名称或简称匹配，歧义先选项目；明确的“它 / 这个项目”追问沿用当前项目，陌生名称不套用旧项目。从客户档案点击「围绕此对象发起对话」或在资料选择器中选定客户后，普通问答使用该客户的基本信息与最近 8 条记录，直到更换或清空范围。关闭开关后，本轮不读取客户或项目档案。
5. 已有成功对话后，首次带入、切换或解除档案背景，都需确认开始新对话，避免混用历史。要从已选客户改为按名称检索项目，请先清空范围或选择项目。客户背景不沿关联关系读取联系人详情、其他客户、项目、文件正文或微信原文。

2026-10-23 调整：输入框与发送按钮保持在工作区底部，对话回复、任务进展和回答偏好在中间阅读区滚动。首屏提供三个示例按钮，只填写需求，不自动发送或执行。输入框标明用于普通问答 / 新任务；补充运行中的任务仍使用该任务卡内的输入框。临时会话的保留规则现在显示在页首。

任务识别支持否定、转折和常见省略表达，例如“先不要生成 PPT，帮我复盘本周客户进展”进入客户复盘，“把方案整理成 8 页 PPT”进入演示文稿表单。“解读招标文件”进入专用招投标页面，保留原需求；用户选择投标项目、核对已登记原件并确认后才创建任务，不会将普通资料选择自动转成招标原件。

完整聊天记录不保存到业务库或聊天文件。刷新、关闭页面或重启应用后开始新对话；页面退出通知丢失时，服务端闲置会话在 30 分钟后、下一次聊天请求到来时清理。每段最多完成 20 轮，每条输入最多 8000 字；较小模型还受上下文预算限制。失败或停止的轮次不会进入后续模型上下文，页面保留失败提示及输入草稿。用户明确确认的回答偏好和项目记录可长期保存，见下一节。

## 对话内卡片与明确记忆

- 项目匹配后，回复中展示服务端项目资料卡：客户、负责人、阶段、说明、缺项、最近记录、来源与读取范围。它与本轮发送给模型的项目背景同源，不增加文件正文或微信原文读取。
- 显式选择客户时，使用同样的服务端校验和容量限制展示客户资料卡，并可确认保存到该客户档案。客户和项目背景不能同时提交；更换对象或关闭档案背景时仍校验会话范围。保存完成后提示“尚未纳入正式销售台账或销售行动简报”，避免把档案记录误认为正式登记。
- 项目轮次成功完成后，可展开“补充 / 整理本轮信息”。默认草稿是本轮用户原话，不是模型提取或核验后的事实；超过 2000 字时不预填，避免静默截断。可选择跟进、行动或里程碑，并填写截止日期。
- “仅用于追问，不保存”将表单内容作为新的用户消息继续对话，不写资料库；“确认保存到项目”才追加项目记录。默认只保留填写的内容、来源轮次和时间；另行勾选“同时保留本轮原话”才保存用户原话来源（最多 1200 字，截断有标记），修改草稿不改变原话。不改变阶段、负责人或正式销售台账。重复请求不会重复追加；冲突保留草稿，刷新档案版本后重新确认。会话关闭、过期、失败或取消的轮次不能据此保存，用户仍可在项目资料库手动维护。
- 输入“以后回答简短，先给结论”等明确表达时，本机规则可给出待确认的偏好卡。它不是行为画像或通用语义抽取；不记录点击、浏览频率，不从模型回答中学习。点击“记住这个偏好”后才持久保存。
- “回答偏好”入口支持查看、修改、忘记四类设置：详略、结构、呈现方式、语言。值来自固定白名单，不能保存任意个人资料、指令或敏感画像。多个窗口使用版本校验，冲突不覆盖。
- 默认开启“应用回答偏好”。后续普通对话每轮从本机读取已确认偏好，作为参考数据发送给当前所选模型，并在消息内显示“本轮使用了哪些偏好”。可关闭，关闭后不读取偏好表、不附带偏好或生成建议。忘记仅移除后续读取的设置，不删除既有对话里已经说过的文字；若需隔离旧内容，请开始新对话。工作流任务目前不注入这些偏好。
- 偏好保存在 `data/library/dossiers.sqlite3` 的独立 `chat_preferences` 表中，与项目记录一起按既有资料库方式备份。纯读取不会创建数据库；旧版程序忽略新表，不改变原档案结构。只保存枚举设置及更新时间，不保存偏好原话；项目原话仅在用户勾选保留来源并确认保存时持久化。

卡片由本机可信数据和白名单组件驱动，不解析模型输出中的 HTML/JavaScript，不把文字变成可执行界面。此次不引入 Mem0、图数据库、云记忆服务或新的前端框架；尚未实现通用模型生成布局、自动业务事实抽取、全量历史对话保存或隐式习惯分析。所有写入按钮仍经过本机用户、令牌和 JSON 校验。

新页面提交 `ui_version: 1` 才启用 `ui` 流事件和成功终态的 `cards` 字段；未声明版本的旧页面仍只接收原文字协议。`use_preferences` 也由页面显式传入，旧客户端默认不读取偏好，避免升级后无提示扩大模型上下文。

## 模型与边界

- 支持现有 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages API，以及 Windows 下已注册、校验过启动文件的 Claude Code / Codex CLI 后端。不得自动换供应商或回退到其他账户。
- 未选择客户、未匹配项目，或关闭档案背景时，仅发送固定聊天说明、本段已成功完成的用户/助手文字和本轮输入。选择客户或匹配项目后额外发送服务端重建的有限档案背景：基本信息、最近 8 条已保存记录、缺项和来源时间，不读取文件正文、微信原文或浏览器。详见《业务资料库与三入口》的项目索引说明。
- 单独使用无工具模型传输，不创建 Pi Agent 会话，不加载项目技能、扩展或历史会话。只读取所选供应商凭据、选定项目的白名单背景和用户启用的已确认回答偏好；凭据更换、接收方或思考配置改变后，旧对话必须重开。凭据指纹只存在进程内存中。项目背景和偏好每轮重新读取，原始背景不留在会话历史中；回复文字仍可能引用其中事实。
- CLI 使用当前 Windows 用户的当前登录，沿用既有关闭原生工具、项目/用户定制和会话复用的启动参数。切换 CLI 登录账号后应新建对话。此处不是操作系统级文件沙箱，不能保证同用户 CLI 二进制在 OS 层没有文件读取能力。
- 每轮采用随机私有工作目录；新运行根是当前用户目录下的 `Agent4MarketFreeChat`，既有目录只验证权限，不修复或使用不安全目录。对话和凭据通过 stdin 传入，不放在命令行或配置文件中。
- 只接受同机、同 Windows 用户及登录会话的请求，并校验请求令牌和 JSON 类型。模型回复按纯文字显示，不执行 HTML，也不加载其图片或链接。
- 服务端最多同时生成 2 轮、缓存 8 段会话。请求超时 180 秒；回复文字上限 128 KiB，API 原始响应上限 2 MiB；HTTP 写入超时 5 秒。停止、超时和连接关闭会中止当前请求；Windows 进程树由 kill-on-close Job 管理。POSIX 暂不提供 CLI 自由聊天。

所有模型验收均为合成数据；没有读取真实 CLI 登录、发送业务资料或实际调用收费模型。

- `tsc --noEmit` 以及既有模型、HTTP 和请求头回归测试。
- `npm run test:chat-assistance`：偏好规则、确认/修改/忘记、跨进程持久化、版本冲突、模型范围、已完成轮次授权、幂等项目记录和流式 UI 事件。
