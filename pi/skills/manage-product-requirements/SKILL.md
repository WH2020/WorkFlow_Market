# 产品需求管理

## 开始前

读取已有产品发现、用户证据、业务目标、系统约束和历史决策。证据不足时保留假设，不把提出者意见自动升级为需求。

## 工作流

1. 先建立“已确认、暂定、待确认”清单。一次只核对一个会显著改变产品方向、范围、接口、风险或交付物的问题；遇到“所有用户、尽快、体验更好”等模糊表述时追问可观察定义，发现证据和结论矛盾时直接指出。信息已足够时停止机械追问。
2. 明确目标用户、问题、产品目标、成功指标、范围和非目标。
3. 按“必须实现、建议实现、可以延期、明确不做”划分需求，并说明依据。
4. 绘制主流程及加载、空状态、错误、超时、权限不足、撤销和恢复流程。
5. 为重要需求写可验证的验收标准，并建立“证据 → 需求 → 设计 → 验收”追踪关系。
6. 记录性能、成本、安全、隐私、兼容、可维护性、外部依赖和数据要求。
7. 对重大变更记录原因、影响、迁移/回滚路径和待决策人，不静默覆盖旧结论。

## 输出

- 结论先行的 PRD 或需求变更单。
- 需求清单、优先级、验收标准和追踪表。
- 假设、未知项、风险、依赖和决策请求。
