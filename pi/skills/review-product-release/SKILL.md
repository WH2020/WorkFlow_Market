# 产品发布评审

## 发布前

1. 核对版本目标、范围、验收结果、遗留问题、数据迁移、兼容性、隐私安全和外部依赖。
2. 明确灰度策略、监控指标、告警阈值、负责人、值守、回滚触发条件和恢复步骤。
3. 检查帮助文档、客服话术、销售通知、内部培训和用户沟通是否就绪。
4. 按阻断项、可带风险发布项、可延期项分类，不用总体完成率掩盖关键风险。
5. 输出 Go / Conditional Go / No-Go 建议、证据、条件、责任人和最晚关闭时间。

## 上线后

1. 对比基线、目标、护栏和异常，区分已证实变化、相关性判断和待验证原因。
2. 复盘故障、用户反馈、支持成本、未命中假设和流程缺口。
3. 形成继续放量、保持、修复、回滚或停止的建议，并更新需求与路线图决策记录。

不得代替有权负责人批准高风险发布；关键验证缺失时明确暂停条件。
