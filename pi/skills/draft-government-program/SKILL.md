# 政府合作方案

## 逐项核对

一次只核对一个会改变方案方向的关键问题：地区、汇报对象、合作目标、公司可承诺能力、周期、预算口径和输出格式。保留已确认、暂定和待确认项；资料不足时列缺口，不自行编造案例、投资、产值、就业或政府承诺。

## 工作流

1. 读取现有公司资料、历史方案、知识快照和相关业务台账。
2. 先用 `web.search` 发现公开一手来源，再用 `web.open` 读取正文，核验当地最新政策、产业基础、主管部门和已落地项目，记录文件名、发布单位、日期和链接。搜索摘要只作为线索，不能作为政策条款的唯一证据。
3. 建立“地方诉求—公司能力—建设内容—价值指标”对应关系；公司不具备的能力明确标为合作方或待补齐。
4. 形成现状与机会、合作目标、建设内容、实施阶段、双方分工、KPI、预算口径、数据合规、风险和退出条件。
5. 投资、收入、税收、就业和进度使用可追溯测算；没有依据时写“待双方测算确认”。
6. 通过来源、承诺边界和可验收性检查后，到 Approval 节点请用户确认正式承诺。
7. 需要正式文件时使用 `$create-director-documents`；需要演示汇报时使用 `$build-director-decks`。

## 质量门槛

- 每项政策引用可追溯，地域和有效期明确。
- 每项建设内容对应真实能力、合作方能力或待确认缺口。
- KPI 可测量、有周期和责任主体。
- 不用口号替代项目机制，不自动对外发送。
