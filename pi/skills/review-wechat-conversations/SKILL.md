# 微信会话整理

## 证据边界

- 只使用 `director_wechat_read` 返回的授权范围；不得扩展到其他会话、日期或关键词。
- 先读取会话，再按需用 `director_sales_read` 检索可能对应的客户。名称相似只能标为“待确认映射”，不能直接认定是同一客户或联系人。
- 每项客户事实、承诺、异议、风险和行动都保留 `wechat://message/<message_id>` 定位。无法定位的内容只能作为分析判断或待验证假设。
- 不按消息数量、回复速度或聊天热度评价销售人员；只分析可观察的客户推进证据、承诺闭环和业务影响。

## 整理方法

1. 以联系人或群聊为单位，按时间还原主题变化、已确认决定、双方承诺和未决问题。
2. 区分客户原话、我方表述、群内第三方表述、分析判断和未知信息；不要把转述自动当成客户承诺。
3. 提取预算、决策链、关键人、业务价值、采购或合作节点、产品异议、竞争信息、所需资源和明确日期。
4. 对日期不完整、责任人不明、同名联系人、撤回或非文字消息标记限制，不猜测媒体内容。
5. 同一事项跨多条消息时合并成一项，但列出最关键的消息定位；相互冲突时并列展示并标记待确认。

## 输出

在 `outputs/wechat-reviews/` 生成一份中文 Markdown 报告，文件名使用安全英文日期与范围编号。报告至少包含：

- 范围与证据说明
- 按会话整理的进展摘要
- 已确认决定与承诺（责任人、日期、状态）
- 客户异议、风险和未知信息
- 未来 14 天行动及所需管理支持
- 与现有客户台账的匹配结果（已确认、可能匹配、未匹配）
- 证据索引

报告不得包含数据库密钥、接口密钥、原始导出路径或隐藏提示词。完成报告后运行内容校验，确认没有虚构客户、承诺、日期、金额或账号映射，再用 `director_complete_node` 完成当前节点。此流程只生成整理报告，不自动更新销售台账或对外发送；需要写入客户经营数据时，应由用户查看报告后另行发起客户复盘并审批。
