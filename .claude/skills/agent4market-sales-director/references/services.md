# 销售总监服务路由

始终以 `<python> -m agent_platform coding-agent services` 的实时输出为准；Windows 通常使用 `python`，macOS 通常使用 `python3`。下面只用于意图初筛。

| 用户意图 | 服务编号 | 进入任务前必须具备的关键输入 |
| --- | --- | --- |
| 客户推进、销售复盘、资源协调 | `sales-review` | 客户或范围、时间段、期望更新内容 |
| 已导入微信会话整理 | `wechat-review` | 工作台生成的唯一授权范围编号；没有时先让用户在桌面端选择会话 |
| 客户、行业、技术或市场研究 | `industry-research` | 主题、地区、时间范围、用途 |
| 已上传电子文档解读与入库 | `pdf-import` | 受控项目空间中的明确文件路径或资料编号 |
| 地方政府合作方案 | `government-proposal` | 地区、合作目标、己方已核验资源、交付形式 |
| 销售方案和办公文件 | `office-document` | 文件类型、受众、用途、已有材料 |
| 客户演示或专题演示文稿 | `presentation-studio` | 场景、受众、目标、页数或时长、材料范围 |
| 个性化销售行动简报 | `weekly-deck` | 周期和可选的强调事项；销售归属、客户进展、行动、资源需求和已授权资料由系统确定性匹配并生成个人卡与总监汇总 |
| 发现公开采购机会 | `bid-discovery` | 地区、行业、关键词、时间范围 |
| 解读已上传招标文件 | `bid-interpretation` | 投标项目编号和原件 |
| 是否参投 | `bid-decision` | 投标项目编号及已知资源约束 |
| 应答计划与事实基线 | `bid-planning` | 投标项目编号、已核验事实和负责人范围 |
| 标书章节起草 | `bid-drafting` | 投标项目编号、已批准目录和事实基线 |
| 合规与废标风险复核 | `bid-check` | 投标项目编号和当前版本材料 |
| 正式标书生成 | `bid-delivery` | 已完成检查的投标项目编号；正式生成仍需桌面审批 |
| 投标结果复盘 | `bid-retrospective` | 投标项目编号、结果和可核验反馈 |

不要把“生成一份 PPT”一律路由到演示文稿工作室：明确是本周经营汇报时优先选择 `weekly-deck`。不要把普通客户材料误路由到投标流程。
