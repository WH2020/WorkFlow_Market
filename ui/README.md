# 总监工作台（本地界面）

这是一个面向非技术用户的本机控制界面，不需要 Node、浏览器构建工具或第三方服务。

## 启动

在仓库根目录执行：

```powershell
python ui/server.py
```

macOS 使用 `python3 ui/server.py`。首次安装请先运行仓库根目录的 `scripts/setup-windows.ps1` 或 `scripts/setup-macos.sh`；完整说明见 `docs/双平台安装部署.md`。

浏览器打开 `http://127.0.0.1:8765`。可用 `--port 8766` 更换端口。服务只绑定 `127.0.0.1`，不会暴露到局域网或互联网。

## 使用方式

1. 选择“市场总监”或“产品总监”，再选择服务。
2. 填写任务说明并提交。界面会在 `.pi/director-runtime/requests/` 创建一条请求；Pi 运行时负责接手它并创建、推进真实任务。无活动任务且岗位不同的时候，Pi 会先安全重载对应 Profile 再接单。
3. 实际任务在 `.pi/director-runtime/tasks/` 出现后，界面展示 DAG、当前节点、审批状态和产物名称。
4. 对“等待审批”的任务先核对页面展示的具体变更和 SHA-256 校验码，再选择批准、驳回或取消。批准同时绑定任务版本、写入意图 ID 和载荷校验码。运行中的节点不允许从工作台并发取消；需要中止时在 Pi 使用 `/director-cancel`。界面只写入 `approval_request`，不会自行推进普通节点、更改销售数据或调用外部服务。

### PPT 工作室

选择“PPT 工作室”或“周五工作汇报”后，普通任务输入框会切换为结构化 brief：场景、处理模式、受众、目的、使用场合、语言、演讲时长、4–10 页、保密等级、输出文件名、期望决策和三套设计风格。资料范围首版固定为“公开网页 + 当前 Profile 知识库”，本地 PDF 需先走“PDF 资料入库”；不要把秘密信息写进公开检索主题。提交后仍由 Pi 依次完成资料读取、plan、大纲确认和正式生成审批。

等待大纲确认时，页面以便利贴展示每页结论。可以直接改标题并拖动排序。点击“按此大纲创建修订任务”后，工作台会安全驳回旧大纲并创建一个新任务；不会直接编辑 `.pi/director-runtime/presentation-plans/`，也不会把旧 Approval、证据 registry 或写入意图复制给新任务。正式 PPT 只有在最终精确载荷批准且逐页 QA 通过后才出现在 `outputs/`。

审批写入采用任务 `version` 的乐观并发检查、冻结载荷哈希、与 Pi 共用的独占锁和同目录临时文件原子替换。Pi 运行时需要再次校验意图 ID、哈希并执行合法的状态转移；如果版本或内容变化，界面会要求刷新后重新操作。页面启动时获得一次随机请求令牌，修改请求必须携带该令牌；服务同时限制 Host、内容类型和浏览器加载来源。

## 数据与边界

- 数据摘要只显示台账文件是否存在、更新时间和行数；不会把客户、联系人、聊天或业务记录发送到浏览器。
- 产物区域只显示 `outputs/` 的文件名和修改时间，不提供自动外发。
- 请勿把 `.pi/`、真实 `data/` 或 `outputs/` 提交到 Git；仓库的忽略规则已覆盖这些路径。
