# SVG-first Bento Grid 页面

## 方法来源

本参考吸收自 Linux.do 主题 [用 AI 做 PPT 的卡片式/Bento Grid 方法](https://linux.do/t/topic/1782304/2)，访问日期：2026-08-08。该页面是设计方法参考，不作为行业事实或客户事实来源。

## 模式选择

| 模式 | 默认用途 | 输出 | 编辑性 |
| --- | --- | --- | --- |
| `native` | CEO 周报、数据表、需要逐项改字的正式文件 | 原生 PPT 文本、形状和图表 | 最高 |
| `svg-first` | 行业洞察、客户叙事、复杂信息架构和视觉重点页 | 1280×720 SVG 页面，可选封装为 SVG 图片型 PPTX | SVG 对象级编辑；文本不等于原生 PPT 文本框 |

没有明确指定时，数据密集、需要多人二次编辑的文件使用 `native`；视觉叙事、并列比较或信息层级复杂的页面使用 `svg-first`。一个演示文稿可以混用两种模式，但必须在逐页策划稿中标明模式。

## 页面契约

SVG-first 输入使用以下结构：

```json
{
  "deck": {
    "title": "演示文稿标题",
    "theme": "industry-research",
    "width": 1280,
    "height": 720
  },
  "slides": [
    {
      "title": "结论式标题",
      "subtitle": "本页回答的问题",
      "layout": "hero-grid",
      "source": "来源：文件或链接",
      "cards": [
        {
          "eyebrow": "证据",
          "title": "卡片标题",
          "value": "42%",
          "body": "一段事实或解释。",
          "bullets": ["补充事实", "管理含义"],
          "tone": "accent"
        }
      ]
    }
  ]
}
```

## 布局规则

1. 画布固定为 `1280×720`，页面边距至少 48px，卡片间距至少 20px。
2. 布局由内容数量和重要性决定，不为了填满网格而增加卡片。
3. 最大卡片承载最重要结论；辅助证据使用较小卡片。
4. 支持 `single`、`two`、`three`、`hero-grid`、`mixed` 和 `auto`。
5. 每页只有一个中心结论；卡片标题使用结论或问题，不使用无意义的栏目名。
6. 不使用渐变、装饰性光球或整页背景图片；颜色用于区分层级和风险。
7. 事实、判断和待确认内容在卡片中显式标记，来源统一放在页脚或卡片来源字段。
8. 文本超过卡片容量时缩小字号或拆页，不允许通过溢出隐藏内容。

## 生产和检查

1. 先完成需求、资料、页面结构和逐页数字便利贴。
2. 用 `build_svg_bento_deck.py` 生成 SVG 页面和 manifest。
3. 需要交付 PPTX 时，使用脚本的 `--pptx` 选项；该文件中的 SVG 是图片对象，后续修改优先回到 SVG 输入重新生成。
4. 用 `validate_svg_deck.py` 检查 XML、画布尺寸、页面边界、占位符和卡片数量。
5. 用 PowerPoint 或浏览器逐页查看；自动检查不能替代人工检查字体、中文断行、对齐和视觉节奏。

## 不能承诺的内容

- SVG 进入 PowerPoint 后不保证转换为原生文本框和独立形状。
- 没有可验证来源的数字、案例或政府承诺不得因视觉效果直接上版。
- 自动布局是初稿生产工具，复杂页面仍需人工调整卡片顺序、信息密度和讲述节奏。
