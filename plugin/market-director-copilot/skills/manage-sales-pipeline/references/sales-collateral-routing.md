# 销售材料路由与治理

## 请求入口

创建或复用销售材料前，至少确认：

- 对应客户或机会、当前阶段和本次希望推进的动作。
- 使用者、接收者及其决策角色。
- 使用场景、交付格式、截止时间和负责人。
- 已确认的客户问题、异议、证据和可公开能力。
- 已有材料能否复用，以及必须针对本次机会修改的部分。

信息不足时，只询问会改变材料类型、核心论点或承诺边界的内容。

截止时间紧且格式未指定时，给出一个推荐产物和一个轻量备选，将必须确认的问题合并为一次询问；等待确认期间先整理已有证据、缺口和大纲，不因非关键字段缺失停止准备工作。不得以赶时间为由跳过事实、能力、价格、案例授权和对外发送确认。

## 按阶段选择

| 销售阶段 | 优先材料 | 目的 |
| --- | --- | --- |
| 线索 | 简介或场景概览 | 判断是否值得进入需求沟通 |
| 需求确认 | 需求回顾、场景一页纸 | 确认问题、影响和评价标准 |
| 方案设计 | 客户方案、演示脚本、技术说明 | 连接客户问题与解决路径 |
| 预算/立项 | 价值测算、内部推动材料、项目建议 | 支持预算和内部决策 |
| 试点/验证 | 试点计划、验收指标、实施清单 | 固化范围、责任和成功标准 |
| 商务推进 | 正式提案、决策清单、异议速查 | 推动价格、合同和采购流程 |
| 赢单 | 经授权的案例简报 | 沉淀可复用证据 |

阶段不是唯一依据。材料必须同时匹配本次接收者：经济决策者关注价值、成本和风险；技术评估者关注架构、集成、安全和实施；实际使用者关注流程与使用成本；内部推动者需要便于转述的论点、证据和下一步。

## 产物路由

| 产物 | 执行 Skill |
| --- | --- |
| 销售演示、客户汇报或路演 PPT | `$build-market-decks` |
| 一页纸、提案、案例简报、异议速查、演示脚本、角色卡或销售手册 | `$create-office-documents` |
| ROI 或价值测算表 | `$create-office-documents`，使用可审计的 Excel 输入、公式和假设 |
| 基于真实沟通的异议或演示改进 | `$review-sales-conversations` 后再生成材料 |

竞品战卡、冷启动外联文案、产品定价与包装不属于本路由；需要时单独确认范围和证据，不从客户聊天或现有报价中自行推导。

## 资产台账

将可复用材料登记到 `data/sales/sales-assets.csv`。至少记录资产类型、适用范围、客户（如适用）、适用阶段、接收者角色、用途、负责人、版本、文件路径、证据来源、授权状态、脱敏核验状态、验证日期、下次复审时间和销售反馈。

`scope` 只能是 `generic` 或 `customer-specific`；`authorization_status` 使用 `unknown`、`pending`、`approved` 或 `not-required`；`deidentification_status` 使用 `unknown`、`pending`、`passed` 或 `not-applicable`。`customer-specific` 资产必须有 `customer_id`，不得直接作为其他客户或通用资产复用。

使用以下状态：

- `draft`：尚未完成内部核验。
- `internal-review`：等待事实、品牌、技术或商务负责人确认。
- `active`：可以在登记范围内使用。
- `stale`：证据、产品能力、政策或价格可能过期，不得直接对外使用。
- `retired`：已停止使用，仅保留历史记录。

材料正式启用前由负责人确认。只有 `status=active` 且授权、脱敏、证据和复审日期均满足要求的资产才能复用；`draft`、`internal-review`、`stale`、`retired`、`authorization_status` 为 `unknown/pending` 或 `deidentification_status` 为 `unknown/pending` 时硬阻断对外使用。复用时先检查客户信息、价格、承诺、案例授权、日期和来源是否仍然适用。每次使用后记录销售反馈和实际推进结果，定期淘汰无人使用、内容重复或已经失效的材料。

登记或复用前运行（从 Project 根目录执行）：

```powershell
python plugin\market-director-copilot\scripts\validate_sales_assets.py --file .\data\sales\sales-assets.csv
```

校验失败时只能修正台账或把资产降级为 `internal-review`/`stale`，不得绕过校验直接标记 `active`。
