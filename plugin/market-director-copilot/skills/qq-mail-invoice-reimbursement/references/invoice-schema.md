# 发票与报销字段规则

## 明细字段

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 序号 | 是 | 从 1 开始连续编号，异常行也保留编号。 |
| 发票日期 | 是 | 使用发票开票日期，格式 `YYYY-MM-DD`。 |
| 发票类型 | 是 | 例如增值税电子普通发票、增值税专用发票、数电发票、其他。 |
| 销售方 | 是 | 从发票原件读取，不用邮件发件人替代。 |
| 销售方税号 | 否 | 原件有则填写。 |
| 购买方 | 是 | 从发票原件读取。仅公司抬头且与目标报销主体匹配的发票可纳入；个人姓名抬头直接排除，主体不一致或无法确认时标记异常。 |
| 购买方税号 | 否 | 原件有则填写，并用于匹配目标公司；公司抬头缺税号时标为“待人工核对”，不得直接计入可报销金额。 |
| 发票代码 | 否 | 数电发票通常没有传统代码，缺失不视为错误。 |
| 发票号码 | 是 | 作为首选去重键的一部分。 |
| 校验码 | 否 | 电子发票原件有则填写，不能从邮件正文猜测。 |
| 不含税金额 | 是 | 使用数值，不带 `¥` 或货币符号。 |
| 税额 | 是 | 使用数值；免税或不征税时按原票表达。 |
| 价税合计 | 是 | 使用发票上的价税合计，优先作为报销金额。 |
| 币种 | 是 | 人民币或原票币种。 |
| 费用类别 | 否 | 仅在发票或邮件明确支持时填写，否则为“待补充”。 |
| 报销事由 | 否 | 仅使用用户提供或邮件明确说明的事由。 |
| 归属项目/部门 | 否 | 无依据时为“待补充”。 |
| 来源邮件 | 是 | 发件人、主题和日期的可读摘要，便于追溯。 |
| 原始附件路径 | 是 | 相对于报销单目录的路径；多个格式用分号分隔。 |
| 核对状态 | 是 | `已核对`、`待人工核对`、`异常` 或 `重复未计入`。 |
| 备注 | 否 | 记录识别失败、金额冲突、重复依据等。 |

## 去重与金额规则

1. 首选唯一键为 `发票代码 + 发票号码`；代码缺失时使用 `发票号码 + 校验码`，再缺失时使用文件哈希与来源邮件组合。
2. PDF、OFD、XML 是同一发票的不同附件格式时只计一次价税合计；原件可以全部保存。
3. 只使用发票原件的价税合计计算报销总额。订单、付款、物流或邮件摘要金额只能作为线索。
4. `价税合计` 应与 `不含税金额 + 税额` 一致；舍入差异需写入备注并放入异常表。
5. 任何缺少发票号码、价税合计或原始附件的记录不得标记为“已核对”。
6. 只有购买方名称和纳税人识别号与目标公司一致的发票才可标记为“已核对”并计入可报销金额。个人抬头标记为“异常”，备注“个人抬头排除”；其他公司或无法确认的公司抬头标记为“异常”或“待人工核对”。

## 汇总建议

- 发票总张数：仅统计目标公司抬头且未标记为“重复未计入”的明细行；个人抬头和主体不匹配发票只在异常表列示。
- 可报销金额：仅汇总核对状态为“已核对”的价税合计。
- 待核对金额：汇总“待人工核对”和“异常”行，单独列示。
- 按费用类别汇总时，把“待补充”作为独立类别，不要混入已确认类别。
- `报销明细` 按购买方、发票日期、发票号码升序排列；不要为每个抬头拆分独立工作表。
- `按抬头汇总` 使用购买方名称和税号作为分组键；`按月汇总` 使用发票日期的 `YYYY-MM` 作为分组键。
